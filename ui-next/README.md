# Jellyfin UI Next

An experimental Jellyfin web client built with Preact and Vite. UI Next is the only web client in the standard image and is served at `/web` by the Jellyfin-version and `latest` tags.

## Current capabilities

- Playback → Live sessions details shows server-reported pipeline stages for active transcodes. Playback → Transcoding opens the same session details from the active-transcodes list. The diagram shows stage order and format labels; it does not infer branches.
- Jellyfin username/password sign-in
- Public-user picker, Forgot password? (Jellyfin PIN reset) and server branding (login disclaimer, splash screen, custom CSS) on the sign-in screen
- Account screen for your own password and profile image; device-local Controls (game controller navigation, smooth scrolling)
- Display screen (profile menu, also on TV): language, theme (dark, light or match the system), text size (90–130 %) and reduced motion. Theme, text size and motion are stored per browser; the language uses the per-user `<userId>-language` browser key. Arabic, Persian, Urdu and Hebrew switch the layout to right-to-left; the seek bar, player controls and Live TV guide keep their left-to-right time axis. The player always stays dark
- Player chapters, version choice, secondary subtitles, caption appearance/burn-in settings and per-type segment skipping
- Favorites page across libraries (24 per group with Show more), typed people/artist/genre/studio search sections, and a per-user Home screen editor (order, visibility, per-library Latest) with Continue listening/reading and For You rows
- Seerr requests, when the Seerr plugin is configured: search adds a **Request from Seerr** section with titles outside the library, including ones already requested or processing (labelled Requested, Processing or Partially available); home adds **Movies beyond your library** and **Shows beyond your library** rows personalised from the taste profile's top genres and rating floor. A card opens a request sheet (focus-trapped, Back/Escape closes it, TV remote friendly) that sends the request and labels the card Requested. Refusals show fixed messages (parental controls/permissions, already requested, rate limited, Seerr unavailable). The rows are a separate **Beyond your library (Seerr)** section in the Home screen editor, and nothing Seerr-related is shown when the gateway is disabled or unreachable
- Library modes per type (TV Suggestions/Upcoming/Episodes, music albums/artists/songs, photo and video folders), Search this library, multi-value and combinable filters, more sorts, and Thumb/Banner layouts
- Bulk curation: a library **Select** mode lets you pick up to 200 titles (or select all loaded), then mark played/unplayed, favorite/unfavorite, add to a collection, or delete with a confirmation step. Requests run four at a time; items the server does not allow are skipped, failures stay selected and the summary reports succeeded, failed and skipped counts
- Play queue and autoplay: library cards and the bulk bar offer Play next / Add to queue, playlists and collections offer Play all, Shuffle and play-from-entry, and the player has queue-aware previous/next, shuffle and repeat (off, all, one). When a title ends an Up next card counts down 10 seconds (Play now, Cancel, or Back) to the next queued title or, unless *Automatically play the next episode* is off, the next episode. The queue is per browser session, holds video only, and clears when the account changes
- Richer details: ratings, tagline, provider links, compact media tags (4K/HD/SD, HDR, CC), linked cast/crew/genres/studios/tags, similar titles, collections, extras, album tracks, paged playlist entries (Load more; Play all fetches the rest), photo viewer/slideshow, and policy-aware Download, Share, Add to collection and Delete actions. The title, overview and actions sit in a capped hero; cast/crew, genres/studios, similar titles and the paged title list render in a full-width section below, so crew chips show `Name · Role` and posters are not squeezed into the hero column. The less-frequent actions sit behind a **More** menu on the detail page; **Share** copies a `?item=<id>` link that opens the title in UI Next
- Playlist curation: Add to playlist (existing or new) from details, library card menus and the bulk bar; editable playlists offer rename, move up/down and remove. Reloading the page reopens the current page instead of Home
- Separate **Continue with SSO** and **Continue with Quick Access** sign-in routes, with username/password sign-in as a fallback
- Quick Access uses Jellyfin Quick Connect on desktop and TV; TV web wrappers open on this route by default, while SSO is offered on non-TV clients only
- Profile menu with modal Quick Connect authorization, playback and subtitle preferences, taste profile, remembered-user switching, sign-out, and the administrator workspace; TV menus show only Switch user and Sign out
- A “Who's watching?” switcher with large colored profile tiles, current-user and sign-in status, and an another-user sign-in tile. The switcher hides the top navigation and offers an on-screen Back button plus Back/Escape. It focuses the current profile on opening, supports directional navigation with keyboard/TV remote arrows, and returns with Back/Escape. The grid wraps on smaller screens and enlarges tiles on TV clients.
- Metadata editing from item details (desktop and mobile; not on TV): administrators get Edit metadata (titles, ratings, dates, overview, genres, tags, studios, cast and crew, external IDs with provider links, series air schedule, per-item language/country, display order, 3D format, and whole-item or per-field locks), Images (list, delete, reorder backdrops, upload, and search online images by type and provider), Identify (search providers by name, year or external ID, then apply a match with an optional image replacement) and Refresh metadata (scan, fill missing, or replace all, with optional image replacement and trickplay regeneration). Users with Jellyfin's subtitle-management permission can search, download and upload subtitles on videos, and users with the lyric-management permission can search, download, upload and delete lyrics on songs; deleting external subtitles is administrator-only. Saves re-read the item and send only the fields you changed, so concurrent server updates to other fields are kept, and the details page reloads after each change. Closing the editor with unsaved changes asks first.
- Administrator workspace for server overview, Users & access (including SSO/RBAC mapping editing and chunked Emby userdata import), Libraries, Playback, Live TV, Metadata, Recommendations, Infrastructure, Activity, and System. It uses Jellyfin and Pgsql APIs for live sessions, scheduled tasks, activity, library counts, storage, cache statistics, playback-method aggregates, taste evaluation and plugins. Playback → Transcoding edits the server-wide encoding settings (hardware acceleration and decoders, encoding formats including this fork's codec fallback and parallel race, tone mapping, encoder quality, audio, paths, throttling and Live TV stream buffering/probing), showing only the fields that apply to the chosen acceleration type and flagging types or decoders FFmpeg did not detect. Plugins lists installed plugins with available updates, a catalog from the enabled repositories with per-version install, update and downgrade (showing each version's changelog as plain text), uninstall, and repository management, then offers a server restart once changes are pending. Metadata (also opened from the profile menu's Metadata manager) browses a library by folder with breadcrumbs, filters by type, searches the library, flags locked items and items without external IDs, and opens the same metadata editors for any row; its Display, Metadata and NFO tabs edit library display options, the date-added source, default metadata language and country, generated chapters and chapter image resolution, and NFO settings (watch-data user, release date format, image paths, path substitution and extrathumbs). On active-standby HA servers the top bar shows "HA leader · epoch N" or a red "Standby instance" chip. The Overview adds a High availability card: role, epoch, instance, leader since, heartbeat, the `/health/ready` result, and failovers seen this session, detected from the `X-Jellyfin-Ha-Role` / `X-Jellyfin-Leader-Epoch` response headers and `/Pgsql/Stats`. Standby, not-ready and recent failovers appear as health issues; single-instance servers show none of this. Features are omitted or explicitly marked unavailable when the connected server does not expose the required data; environment-controlled settings are read-only.
- Home page opens with a personalized movie + TV hero and library chips, followed by a rhythmic feed of horizontal carousels and cinematic spotlight breakouts. The feed includes continue watching, true Next Up from `/Shows/NextUp`, just added, On Now, Jellyfin recommendation groups, and themed Explore rows. A single fallback “Explore your library” rail has a **Show more** card that loads another page when selected. Next Up explicitly includes series without a resumable episode and refreshes after reported playback. Matching data can add BoxSet collection, director recommendation (4+ items), highly-rated (8+) unwatched movie (older than six months), or resumed TV-episode spotlights. Spotlights use backdrop imagery, compact metadata, Play/Resume, favorite/watchlist, and Details actions. The feed virtualizes to the current block plus one neighbor on either side and uses measured spacers, lazy rail images, and explicit spotlight background release when blocks leave the render window.
- Spotlight/feed blocks use a three-block render window with measured-height placeholders, a 600px observer margin, lazy rail images, and image clearing when offscreen spotlights unmount; TV directional navigation can move between spotlight actions and the next rail.
- Mobile hamburger navigation with a left-side library drawer
- Home sections load independently and expose section-specific retry when an endpoint times out
- Library browsing, item details, and a fullscreen direct-play player with custom on-screen controls. Search lives behind a header search button: desktop and mobile expand an inline text box, while TV opens a dedicated search page with a remote-navigable on-screen keyboard on the left and live results on the right. Queries of two or more letters search as you type with stale responses ignored; shorter queries show genre and library suggestions. Result cards label their kind (Live with red highlight while airing, start time for upcoming programmes, episode codes, Series, Movie), and opening a result keeps the query, so Back returns to the search page with results intact. Results load in pages of 40 with a “Showing X of Y” summary and continue as you scroll or through an explicit “Load more results” button; leaving search cancels any request still in flight. Series opened from home, search, Live TV or a library return there with that view's position.
- Library browsing has a compact sticky counter/filter/sort bar, a right-edge `#` / `A`–`Z` scrubber with active-letter tracking and a drag bubble for title sorting, a transient scroll-position marker for other sorts, and grid/list views. The responsive filter popover contains genre/resolution/decade/watch-status controls; the grid removes page headings and uses 2:3 posters with virtualized rows. TV keeps the alphabetical rail visible on the right, and ArrowUp from the control bar focuses the active letter directly; numeric T9 keys continue to jump by title. Scrollbar chrome is hidden while native scrolling remains enabled. It requests filtered `/Items` pages of 80 and retains a sliding window of at most three pages while a fixed-height catalog canvas keeps visible rows plus a two-row buffer in the DOM. Alphabet dragging updates only the bubble until release; a jump locates the boundary with logarithmic, single-item `SortName` lookups, caches that offset for the current query, then fetches one ordinary page and positions it once. Superseded lookups and pages are cancelled, stale responses are ignored, and subsequent paging uses the same absolute catalog coordinates. This also avoids alphabet-boundary cache collisions on older plugin versions. Library posters request `maxWidth=300` at `quality=80` (list thumbnails use 160px). List rows load director names separately near the viewport so expensive full-page `People` hydration cannot block the catalog. Favorite and played state can be changed from card actions, using the server's returned state; a row that no longer matches the active watch filter leaves the list. Folders, collections and playlists list their direct children with a “Back to <parent>” control, and each library remembers its filters, sort, layout and scroll position when you return from details, a series or a child folder. Genre and decade filter options load and retry independently. Detail pages show only actions that apply to the item (Play, favorite, mark watched), show a loading note while full details arrive, list the titles for people, genres, studios and artists, and give episodes “Go to series” plus previous/next links. The player's episode drawer loads one season at a time, so very long series stay fully reachable.
- TV shows open into a continuous episode explorer: series header, sticky season navigation, and a unified scroll feed across seasons. Season deep links use `?show=<seriesId>&season=<seasonNumber>` and those parameters are removed when you leave the show; episodes are paged and neighboring seasons are prefetched while the current season plus adjacent seasons are retained in memory. On very large series, unloaded season space uses measured spacers to preserve scroll position. Delayed season and detail requests cannot move focus or replace a newer selection. Item deep links use `?item=<itemId>` and open that title's details; the parameter is removed once the item opens.
- Responsive layouts and directional-key focus movement for TV remotes. In a show, Left and Right move only between controls in the same episode; Up and Down keep the selected control across episodes and seasons. Artwork Left reaches the matching visible season navigator; moving from a season enters that season's first episode. Empty seasons keep focus on the navigator. Details and playback return to the originating view, episode control, and scroll position; episode details label their destination "Back to show". The narrow TV drawer keeps directional focus within the drawer until it closes.
- TV focus uses solid fills for keyboard keys, library chips, tabs, and primary actions without extra rings. Actions that are already lime turn white on focus. Home, search, and library cards show a rounded lime ring over the artwork, leaving titles and metadata unframed. Other controls retain visible focus indicators. Focus does not scale controls, and desktop keyboard outlines remain available.
- Poster cards keep their title and compact metadata inside a bottom artwork gradient. Badges and progress remain over the poster, while list view keeps its richer text metadata outside the thumbnail. Poster rows use the artwork ratio as their card height.
- Remote navigation reveals the full focused control, including card metadata, with 16px clearance from sticky headers and the bottom of the visible viewport. The visibility check also runs after scrolling, resizing, and virtualized content changes. Controls taller than the available space align at the top. Mouse, wheel, and touch scrolling suspend correction until keyboard navigation resumes; dialogs and the player manage their own scrolling.
- Up and Down within the home feed move to the adjacent rail or spotlight, mounting virtualized blocks before focusing their controls. Appending feed pages preserves the active block by ID. Spotlight entry scrolls immediately so a delayed animation cannot compete with focus visibility or leave the next block unmounted.
- Live TV, when the server has a Live TV library, opens into On Now, Guide, Channels, and DVR. On Now groups what is airing. The guide is a virtualized channel-and-time grid on wide screens and a Now/Next list on small screens. On TV remotes, Left/Right moves through a channel, its favorite control, and actual program cells. Left from the channel control focuses the filter. Up/Down keeps the channel/favorite role or aligns programs by time. When a row has no adjacent program, focus stays put instead of panning the timeline. At a time-window edge, the guide loads more listings before moving focus into them. Day buttons move left and right. Right from the last day focuses the channel filter, and Left from the filter returns to the last day. Up from a day button focuses the selected Live TV tab; Down enters the channel list. Up and Down on the filter change its native selection. Program details keep D-pad focus inside the sheet. Back, Escape, or Close returns focus to the program that opened it. Guide data is requested in four-hour windows. The day picker covers every day the server has guide data for, up to 14 days. Returning from a channel restores the guide's day, filter, time window, loaded channels and the tuned channel. Channel favorites are saved on the Jellyfin account; channel order is saved only in this browser and can be reset. DVR lists scheduled timers, series rules, and recordings. Timers and series rules can be edited for padding, plus new-only, any-channel, any-time and keep-up-to for series. Program sheets offer Edit, Cancel or Stop for existing recordings, and Record Series only for series programmes. Watching a channel uses the fullscreen player. HLS uses HLS.js when supported, with native HLS as the fallback when HLS.js is unsupported.
- Browser Back and Forward move between consumer pages (home, libraries, search, details, series, Live TV, profile screens and the player); tab, season and search-term changes update the current entry instead of adding new ones.
- TV layout is chosen from, in order: `?layout=tv` or `?layout=desktop` in the URL, the "Layout on this device" setting under Playback preferences, the native wrapper's reported layout, then the browser user agent. A native wrapper bridge on its own no longer forces the TV layout.
- Overlays (Quick Connect, the mobile library drawer, Live TV program and timer sheets, library card actions, the narrow admin sidebar) move focus inside when they open, keep Tab inside, close with Escape or remote Back, make the page behind them inert, and return focus to the control that opened them. Search and library grids keep Tab moving through titles that are not yet rendered, and the guide exposes channel/program grid semantics with descriptive program names. Consumer error messages describe what to do next rather than repeating raw server responses.
- No UI component library; CSS and Preact only

Playback fills the viewport with a custom on-screen display on the direct-play stream. Episode playback shows the series and episode code in the title, and an episodes tray can jump to another episode without leaving the player. The bar includes previous and next episode, 10-second skip, play/pause, text subtitles with a timing offset, audio tracks when the browser exposes them, playback speed, picture fit, and fullscreen. The volume slider is a desktop hover control and is hidden on small screens and TV remotes. While seeking, the timeline shows a timestamp and a trickplay thumbnail when the server has generated tiles, plus intro and credits markers when media segments exist. Controls fade after a few seconds of playback. Playback start, progress about every 10 seconds, and stop are reported to the Jellyfin session, including when the page is closed, so resume position and played state stay on the server. Video metadata and play, pause, seek, previous, next and Stop actions are exposed to browser OS media controls. Stop—including the common physical media key—leaves the player and reports the current position so resume does not rewind. Details offer Resume and From beginning. Negotiation uses a probed device profile and keeps the server's default audio and subtitle tracks. Audio switches that the browser cannot make locally, image subtitles, removing burned-in subtitles, quality changes and error recovery (Retry, Convert the stream, Try lower quality) request a new stream at the current position. Live streams seek within the browser's seekable window and offer Go live. The player shows a buffering spinner while media waits. It gives HLS.js bounded recovery and opens one fresh Live TV stream after 20 seconds without playhead progress or a native media error. If playback still stalls, it offers Retry, Convert the stream and Try lower quality. The settings menu shows the actual method (direct play, remux or transcode) from this device's session. Speed (up to 3x), picture fit and volume persist per device. Picture-in-picture appears when supported, and iOS falls back to native video fullscreen. Do not use this preview as a replacement for the existing web UI.

HLS.js VOD can buffer up to ten minutes ahead when the device-memory tier and bitrate allow it. The player retains at most 90 seconds of played segments. Its estimated media-buffer budget is 64 MiB when device memory is unavailable or below 4 GB. The budget is 128 MiB from 4 GB to below 8 GB, and 256 MiB at 8 GB or more. Before loading segments, the player recalculates the estimate using the highest bitrate in the HLS manifest, the source bitrate, and the negotiated maximum. HLS.js and browser quotas may evict media sooner. These settings do not set a hard process-memory limit. The seek bar shows played progress separately from buffered segments. After three confirmed stalls in 60 seconds, the player attempts up to two lower-bitrate renegotiations. Live playback follows the available playlist and does not request a ten-minute future buffer. Direct progressive and native-HLS fallback buffering stay under browser control.

When a movie ends without a queued title, the player fades its controls and offers similar titles to play next. Choose a recommendation, Replay, or Back. Queued titles and episode autoplay keep their existing behavior.

Live TV recovery closes the current `LiveStream` before opening its one automatic replacement. UI Next makes at most one automatic reopen attempt per playback.

Music plays in its own engine, separate from the video player, so it keeps playing while you browse. Songs, albums, artists, music genres and playlists that start with a song offer Play, Shuffle, Instant Mix, Play next and Add to queue (also from library cards and the bulk bar); album track rows play the album from that track. A mini-player bar at the bottom expands to Now Playing (also in the top navigation while a queue exists), with seek, shuffle, repeat off/all/one, volume and a queue you can jump in, reorder, trim or clear. Tracks are negotiated with an audio device profile and streamed from `/Audio`; the next track preloads on a second audio element for near-gapless changes. Playback → Music on this device sets volume levelling from Jellyfin's `NormalizationGain` (album, track or off), a 0–12 second crossfade, and gapless album playback (no crossfade between consecutive tracks of one album). The track shows in the browser's media controls (or the native host's), start/progress/stop reports include the queue, a track that fails is skipped, starting a video pauses the music, and signing out stops it.

## Develop

Requires Node.js 22.18+ and npm (`package.json` `engines`; CI and the Docker image use Node 24). The test suite imports the TypeScript sources directly, relying on Node's built-in type stripping (on by default from 22.18) and synchronous `module.registerHooks` to resolve extensionless imports, so older runtimes fail before any test runs. CI runs `npx tsc --noEmit` and `npm test` in the `ui-next` job of `.github/workflows/test.yaml`; the Docker `ui-next-build` stage runs `npm test` before `npm run build`.

Build identity: set `UI_NEXT_BUILD` (the Docker workflow passes the commit SHA) when building. The revision is embedded in the bundle, shown in the profile menu, sent to Jellyfin as the client version (`0.1.0+<sha>`), and written to `dist/build.json` (`{ revision, builtAt }`). After sign-in the app fetches `build.json` with `no-store`; when the served revision differs from the running bundle it shows a Reload notice, so a stale cached bundle is not mistaken for a server regression. To verify a deployment, compare the `build.json` served next to UI Next's `index.html` (or the profile menu) with the image's commit.

```sh
npm install
npm run dev
```

After installing dependencies, you can also start the dev server in VS Code with **Tasks: Run Task → start-ui-next-dev**.

For a development-only backend picker, run `npm run dev:debug` and open the displayed dev-site address ending in `/debug.html`. Enter the Jellyfin base URL (for example `http://localhost:8096` or `https://media.example.net`). The launcher opens the app with the backend prefilled and the app returns to its normal URL after successful sign-in. `?server=...` can also be supplied directly to the app URL. The debug page is excluded from production builds.

To route the app's standard API proxy to a local backend, set the proxy target when starting Vite:

```sh
JELLYFIN_BACKEND_URL=https://media.example.net npm run dev:debug
```

To set the Jellyfin server for the app and skip entering its address on the sign-in screen, provide `VITE_JELLYFIN_SERVER_URL` when starting the dev server:

```sh
VITE_JELLYFIN_SERVER_URL=https://media.example.net npm run dev
```

This value prefills all sign-in flows (including SSO and Quick Connect), hides the editable server field, and is also used as the Vite API proxy target unless `JELLYFIN_BACKEND_URL` is set. Without it, the app keeps its normal saved-server and login-screen behavior. If an existing saved session belongs to a different server, it is not reused.

Vite proxies selected Jellyfin API paths to `http://localhost:8096` for local development. Change those targets in `vite.config.ts` when running the local server elsewhere. The development-only SSO probe checks the backend selected in `/debug.html` through Vite, so SSO availability detection does not require CORS. The probe only contacts the proxy backend (`JELLYFIN_BACKEND_URL` or `VITE_JELLYFIN_SERVER_URL`) plus origins listed in the comma-separated `UI_NEXT_PROBE_ALLOWED_ORIGINS`, and only answers requests from this machine. `npm run dev`, `npm run dev:debug` and `npm run preview` listen on localhost; use `npm run dev:lan` to expose the dev server to other devices (for TV testing), which also lets those devices use the probe. Login and Quick Connect requests use the entered server URL directly; a different-origin backend must allow the dev UI origin in Jellyfin CORS settings for those flows. Production use requires HTTPS except when the UI and server share an origin or for localhost development.

For HTTP backend testing, use the development server only. The app displays a warning because HTTP sends credentials and tokens without transport encryption. Use HTTPS for a real server. Cross-origin backends must allow the dev UI origin in Jellyfin CORS settings.

```sh
npm run build
npm run preview
```

The build is static and is emitted to `dist/`. The Dockerfile's `ui-next` target is also its default target. The workflow serves this build at `/web` under the standard Jellyfin-version and `latest` tags. UI Next includes its own Metadata manager in the administrator workspace. Production output includes a classic Android WebView marker before the Vite module entry. The updated image still needs an on-device startup check; wrapper playback, older TV engines, and performance on physical devices also need testing.

### End-to-end tests

Playwright runs UI Next in Chromium against a loopback fake Jellyfin server. The fixture builder supplies a user, libraries, and media items. The server records sanitized API requests and serves a short WebM for actual playback. The desktop tests cover sign-in, home, library browsing, item details, the detail **More** menu and its `?item=` share deep link, playback reports, profile-menu navigation, plugin settings without a classic dashboard link, the `?layout=tv` override, and dialog focus confinement. A `tv` project emulates a webOS user agent at 1920×1080 and covers the ten-foot UI: D-pad focus travel across the library grid, Enter navigation, remote Back, show-detail season/episode focus, and player OSD focus. The tests do not start Docker or require a real Jellyfin server.

The HLS playback tests use the checked-in `hls-sample.ts` media fixture and fake Jellyfin playlists. The VOD seek test holds segment 2 pending, then checks that a seek to 565 seconds requests segment 56 and resumes playback before seeking backward in the same session. The Live TV test reports native HLS as `maybe` while native media requests fail, then serves a growing HLS `EVENT` playlist to HLS.js. It checks a second playlist reload, a newly published segment request, and no stop report or live-stream close. Other cases cover native fallback without Media Source Extensions and an error when neither playback path is supported. These browser tests do not run Jellyfin ffmpeg or NVENC.

Install the browser once, then run the suite against Vite's development server:

```sh
npm run e2e:typecheck
npx playwright install chromium
npm run e2e
```

To run the same tests against the production bundle, set `E2E_APP=preview`. Playwright builds UI Next, starts `vite preview`, and uses Vite's default preview proxy to reach the fake server:

```sh
E2E_APP=preview npm run e2e
```

The fake server and UI use loopback ports `8097`, `5179`, and `4179`; tests fail if a required port is already in use. The CI `ui-next` job installs Chromium and runs the preview mode. The suite does not validate real Jellyfin behavior, SSO, Quick Connect approval, Live TV, admin pages, Android/WebOS wrappers, or physical devices.

### Translations

UI strings go through `t()` from `src/i18n.ts`, keyed by their English text: `t('Sign out')`, `t('Delete {0}?', name)`. Placeholders use `{0}`. The English message is the key, so source stays readable and a missing translation falls back to English.

`src/boot.ts` loads the signed-in user's language before importing the app, because module-level labels are translated when their module first loads. The lookup tries the exact language, then its base language, then a regional variant, and finally English. Dates and numbers use `Intl` with the active language.

After adding or changing a `t()` message, run from the repository root:

```sh
node scripts/sync-ui-next-strings.mjs
```

The script collects every `t()` literal, writes the English catalogue, and keeps existing locale values for retained messages. The generated files are committed, so Docker builds need no translation source checkout. `--check` fails when the committed files are stale. New or untranslated messages appear in English. `tests/i18n.test.mjs` fails on raw JSX text or literal `aria-label`, `placeholder`, or `title` attributes that bypass `t()`.

Sign-in screens focus the first available control automatically. Up/Down moves between fields and buttons on both desktop keyboards and TV remotes; Left/Right keeps its text-editing behavior inside inputs. Enter activates buttons or submits the form. Another user opens sign-in options on desktop and Quick Connect on TVs; remembered profiles requiring credentials open the password form with the username filled in. During user switching, **Choose a profile** returns to the picker. Remote Back/Escape returns first to sign-in options, then to the picker. TV sign-in controls are enlarged and all sign-in controls have visible focus outlines. Sign-in uses a wide two-column layout with instructions beside the controls, stacking vertically on smaller screens. Quick Connect displays a large code and step-by-step approval instructions; sign-in methods use large labeled buttons, and unavailable Quick Connect is disabled. Password sign-in has larger fields and concise user-facing errors.

## Security notes

- Passwords are sent directly to the configured Jellyfin server and cleared after sign-in; they are not stored.
- The selected server, Jellyfin access token, user, and server ID are stored in `localStorage` so the login survives browser restarts; sign-out revokes the current token and records a signed-out marker so the revoked session is not restored. Earlier `sessionStorage` sessions are migrated once.
- Up to eight remembered user sessions per server are stored locally to support device-local user switching. **Switch user** keeps the old server token valid; **Sign out** revokes the current token and removes it from remembered users. Anyone with access to this browser profile can use remembered sessions, so clear browser storage on shared or untrusted devices. A remembered token is reused only for the server the current account uses and only if it passes the same address checks as the active session; otherwise the password form opens. Before switching, UI Next asks `/Users/Me` who owns the remembered token; a token that belongs to a different user is treated as expired. When a token is rejected, only that token is forgotten. Malformed or oversized remembered-user storage is trimmed rather than trusted.
- All tabs of UI Next in one browser share one signed-in session: signing in or switching user in one tab switches the others, and signing out in one tab signs the others out. A tab never removes a stored session that belongs to a newer sign-in.
- The administrator workspace stays inside UI Next. The image does not include a separate Jellyfin Web dashboard.
- A generated device ID is stored in `localStorage` and reused on later launches. If browser storage is blocked, the app uses one stable in-memory ID for the current page session.
- When an authenticated API request returns HTTP 401, UI Next clears the rejected session and its remembered token, then returns to sign-in with a session-expired message. HTTP 403, server errors, and network failures do not sign you out. Jellyfin revokes previous tokens when the same user signs in again with the same device ID, which can invalidate another open tab. SSO creates a Jellyfin token; UI Next does not hold an OIDC refresh token, so recovery requires another sign-in.
- Server addresses must use HTTPS, except localhost during development.
- Plugins run with full server access. The admin Plugins page asks for confirmation before installing from any repository other than `https://repo.jellyfin.org`, warns before adding an unencrypted (`http://`) repository, never shows install errors from the server verbatim, and does not offer to uninstall or disable the PostgreSQL provider plugin, which the database depends on.
- Metadata editors are offered only to administrators, except subtitles and lyrics, which follow Jellyfin's subtitle- and lyric-management permissions (the server enforces the same rules). Online image, identify and lyric results are validated and bounded; only `https://` image URLs are shown, and their thumbnails load directly from the provider's host with `referrerpolicy="no-referrer"`. External ID links open in a new tab with `rel="noopener noreferrer"`. Uploads are checked before sending: images must be JPEG, PNG, WebP or GIF up to 15 MB, subtitles SRT/ASS/SSA/VTT/SUB up to 2 MB, and lyrics LRC/TXT up to 512 KB. Server error bodies are never shown.
- HA diagnostics read the leadership response headers in one `getAllResponseHeaders()` call, so cross-origin responses that do not expose them produce no console errors. The instance host name comes only from the administrator-only `/Pgsql/Stats`, and the HA state is cleared on sign-out and account or server switch.
- Seerr calls go through the Jellyfin Seerr plugin (`/Seerr/*`); the Seerr API key never reaches the browser. Seerr results are validated and bounded before display, and their posters load directly from `https://image.tmdb.org` (other poster hosts are ignored) with `referrerpolicy="no-referrer"`, so TMDB sees the viewer's IP address but not the UI address.
- Inside a native wrapper, UI Next hands the signed-in user and access token to the host through `NativeShell.onLocalUserSignedIn`. Download URLs given to the host carry the `api_key` query parameter. Only use UI Next in wrappers you trust. URLs passed to the host's `openUrl`, and external links opened in the browser, must be `http://` or `https://`; other schemes are refused.
- Jellyfin API, image, login, and Quick Connect requests use the modern `Authorization: MediaBrowser ...` header. The direct-play video element uses Jellyfin's `api_key` query parameter because native media elements cannot attach custom authorization headers; playback URLs are sensitive and should not be copied or shared.
- The server's [media resource security patch](../docs/patches.md#jellyfin_zzzzzz_media_resource_securitypatch) requires authentication and library visibility for subtitle streams and video attachments. UI Next already includes `ApiKey` on caption URLs. Generated attachment URLs also carry the caller's token for embedded-font consumers, and attachments use download-only responses to prevent media-supplied HTML or SVG from opening under Jellyfin's origin. See the [Plex2Shell-focused review](../docs/known-issues.md#plex2shell-focused-security-review) for findings and limits.
- UI Next probes `/sso/config` and `/QuickConnect/Enabled` on the selected server. **Continue with SSO** is shown only on non-TV clients when SSO is enabled; **Continue with Quick Access** starts Jellyfin Quick Connect, which must be approved from another signed-in device. TV web wrappers start on Quick Access and do not offer SSO. Username/password sign-in remains available as a fallback, and `?local=true` opens that route directly. When `/sso/config?returnUrl=<this page>` reports `codeExchange` (the operator listed the UI address in `JELLYFIN_SSO_UI_RETURN_URLS`), UI Next stores a random verifier in `sessionStorage`, sends its SHA-256 challenge with the login, removes the `#sso_code` fragment from the address bar as soon as the page loads, and redeems the code with `POST /sso/exchange`; the resulting token is checked through `/Users/Me` and `/System/Info/Public` as below. This works for separate UI origins and base paths. Otherwise UI Next marks a same-origin SSO attempt in `sessionStorage`. When the Jellyfin callback returns to `<BaseUrl>/web/`, UI Next accepts only the fresh same-origin credentials written during that attempt, asks `/Users/Me` which user the token belongs to and validates the server through `/System/Info/Public`, then stores its own session only if the token's owner is the expected user. The callback writes hyphenated user GUIDs, while Jellyfin's JSON API returns compact GUIDs. UI Next compares their GUID values and saves the API's user ID. Stale, mismatched-origin, or incomplete credentials do not create a UI Next session. Cross-origin login and Quick Connect requests require Jellyfin CORS to allow the UI origin. If the SSO check cannot reach the server, the sign-in screen says so and offers **Retry** alongside username/password sign-in.
- The profile menu offers server-backed Quick Connect authorization, playback and subtitle user preferences, the Pgsql taste profile, remembered-user switching, sign-out, and the UI Next administrator workspace; there is no generic Profile link. Quick Connect opens in a modal; TVs see only Switch user and Sign out. Playback, subtitle, and taste screens make cross-origin API calls and require Jellyfin CORS to allow the UI origin.

## Compatibility and current gaps

Known gaps against the removed fork-specific Jellyfin Web patches are listed in [Features not yet in UI Next](../docs/features.md#features-not-yet-in-ui-next).

Vite emits a modern bundle plus a syntax-transpiled legacy bundle (currently targeting Chrome 38+, Safari 10+, and Firefox 45+), with the legacy bundle selected by `@vitejs/plugin-legacy`. That is a best-effort web-engine target, not a guarantee for every TV browser. The TV layout supports directional arrows, common Back key codes, and basic media keys. Older webOS/Tizen models must be tested in their actual browser/wrapper.

Native wrappers that load the server's web client and inject `window.NativeShell` (Jellyfin Android, Jellyfin Media Player, and similar) get the app-host contract implemented in `src/native-host.ts`:

The production build emits a classic `main.ui-next-*.bundle.js` marker for Jellyfin Android's WebView startup detector. Android intercepts that request to signal that the web app loaded and inject its native scripts. The marker is a no-op in ordinary browsers; Vite's module entry still starts UI Next. The updated build has not yet been verified on the connected Android device.

- **Identity:** before the first request UI Next awaits `AppHost.init()` (up to three seconds) and uses the host's `deviceId`, `deviceName`, `appName` and `appVersion` in the `Authorization` header, so the server sees the same device the wrapper registers. Missing, invalid or slow values fall back to the browser identity (`Jellyfin UI Next` and a per-browser device ID).
- **Capabilities:** `AppHost.supports()` decides whether Download, provider links, file uploads (images, subtitles, lyrics, profile picture), and the player's fullscreen button are offered. Without a host, desktop and mobile browsers keep them and the TV layout hides them.
- **Profile menu:** Client settings and Download manager appear when the host supports them, and Exit app follows Sign out.
- **Playback:** `AppHost.getDeviceProfile()` can adjust the negotiated device profile; a malformed result falls back to UI Next's own. The player calls `enableFullscreen`/`disableFullscreen`, sends `updateMediaSession` on play and pause and every five seconds while playing, `hideMediaSession` on exit, and forwards volume changes through `updateVolumeLevel`.
- **Android video handoff:** In the official Jellyfin Android app, `NativePlayer.isEnabled()` gates the app's ExoPlayer setting. UI Next sends its current server, user and token to a native sync method; Android validates the token against that server and returns a ready acknowledgement before playback starts. Supported videos then hand off item IDs, queue order, resume position and bitrate preferences; the native app owns its player UI, stream negotiation and playback reports. When ExoPlayer is disabled, the bridge is unavailable, or the account does not match, UI Next uses its browser player.
  The `syncSession` method is supplied by the companion Jellyfin Android change. Upstream app releases that do not include it use the browser player.
- **Session:** `onLocalUserSignedIn` is sent on sign-in and account switch, and `onLocalUserSignedOut` (with the server ID) on sign-out. Downloads go through `downloadFiles` and external links through `openUrl` when the host provides them.

Native-to-web remote commands are not implemented. webOS continues through the HTML `<video>` element. HLS uses HLS.js when supported, with native HLS as the fallback when HLS.js is unsupported. Every bridge call is guarded, so a host that lacks a member or throws behaves like a plain browser. Behaviour on real wrappers is unverified until tested on named devices.

Music uses plain HTML audio elements, not Web Audio. Gapless playback is best-effort: the next track is preloaded and started on `ended`, which can leave a short gap depending on the browser and codec. iPhone and iPad Safari ignore page-set volume, so volume levelling, crossfade and the volume slider do nothing there (the engine detects this and plays without them). Background playback depends on the browser or wrapper keeping the page alive. The music queue lives in the page and is lost on reload.

The browser player fills the viewport with a custom on-screen display on a direct stream: series and episode titles, an episode tray, previous and next episode, text subtitles, playback speed, trickplay thumbnails, and intro or credits markers when the server provides them. It reports playback start, progress, and stop to the signed-in Jellyfin session. For every HLS URL, it lazy-loads `hls.js` and checks `Hls.isSupported()` first, even when the browser reports native HLS support. If HLS.js is unsupported, it uses native HLS when available or shows a playback error when neither path is supported. It negotiates with a probed device profile, renegotiates at the current position for track, quality and recovery changes, and reports playback stops as saved only when the server acknowledges them. Device-local quality limits (bitrate, resolution, audio channels, HLS container) are stored in this browser under Playback preferences. Cross-origin deployments must list the UI origin in Jellyfin's CORS hosts, because the video element loads media and caption tracks with `crossOrigin="anonymous"`. On Android native handoff, the Jellyfin app's own player controls and settings take over. Wrapper compatibility should be considered unverified until tested on named target wrappers/devices.
