# Jellyfin UI Next

An experimental, lightweight Jellyfin web client built with Preact and Vite. Its source stays separate from the `jellyfin-web/` submodule. The Docker workflow can package it as an opt-in test image while standard image tags continue to serve the classic web UI.

## Current prototype

- Jellyfin username/password sign-in
- Public-user picker, Forgot password? (Jellyfin PIN reset) and server branding (login disclaimer, splash screen, custom CSS) on the sign-in screen
- Account screen for your own password and profile image; device-local Controls (game controller navigation, smooth scrolling)
- Player chapters, version choice, secondary subtitles, caption appearance/burn-in settings and per-type segment skipping
- Favorites page across libraries, typed people/artist/genre/studio search sections, and a per-user Home screen editor (order, visibility, per-library Latest) with Continue listening/reading and For You rows
- Library modes per type (TV Suggestions/Upcoming/Episodes, music albums/artists/songs, photo and video folders), Search this library, multi-value and combinable filters, more sorts, and Thumb/Banner layouts
- Bulk curation: a library **Select** mode lets you pick up to 200 titles (or select all loaded), then mark played/unplayed, favorite/unfavorite, add to a collection, or delete with a confirmation step. Requests run four at a time; items the server does not allow are skipped, failures stay selected and the summary reports succeeded, failed and skipped counts
- Play queue and autoplay: library cards and the bulk bar offer Play next / Add to queue, playlists and collections offer Play all, Shuffle and play-from-entry, and the player has queue-aware previous/next, shuffle and repeat (off, all, one). When a title ends an Up next card counts down 10 seconds (Play now, Cancel, or Back) to the next queued title or, unless *Automatically play the next episode* is off, the next episode. The queue is per browser session, holds video only, and clears when the account changes
- Richer details: ratings, tagline, provider links, technical info, linked cast/crew/genres/studios/tags, similar titles, collections, extras, album tracks, playlist entries, photo viewer/slideshow, and policy-aware Download, Share, Add to collection and Delete actions
- Separate **Continue with SSO** and **Continue with Quick Access** sign-in routes, with username/password sign-in as a fallback
- Quick Access uses Jellyfin Quick Connect on desktop and TV; TV web wrappers open on this route by default, while SSO is offered on non-TV clients only
- Profile menu with modal Quick Connect authorization, playback and subtitle preferences, taste profile, remembered-user switching, sign-out, and administrator dashboard links; TV menus show only Switch user and Sign out
- A “Who's watching?” switcher with large colored profile tiles, current-user and sign-in status, and an another-user sign-in tile. The switcher hides the top navigation and offers an on-screen Back button plus Back/Escape. It focuses the current profile on opening, supports directional navigation with keyboard/TV remote arrows, and returns with Back/Escape. The grid wraps on smaller screens and enlarges tiles on TV clients.
- Administrator workspace for server overview, Users & access (including SSO/RBAC mapping editing and chunked Emby userdata import), Libraries, Playback, Live TV, Recommendations, Infrastructure, Activity, and System. It uses Jellyfin and Pgsql APIs for live sessions, scheduled tasks, activity, library counts, storage, cache statistics, playback-method aggregates, taste evaluation and plugins. Features are omitted or explicitly marked unavailable when the connected server does not expose the required data; environment-controlled settings are read-only.
- Home page opens with a personalized movie + TV hero and library chips, followed by a rhythmic feed of horizontal carousels and cinematic spotlight breakouts. The feed includes continue watching, true Next Up from `/Shows/NextUp`, just added, On Now, Jellyfin recommendation groups, and paged “Explore your library” rails so scrolling can continue when recommendation groups are empty. Next Up explicitly includes series without a resumable episode and refreshes after reported playback. Matching data can add BoxSet collection, director recommendation (4+ items), highly-rated (8+) unwatched movie (older than six months), or resumed TV-episode spotlights. Spotlights use backdrop imagery, compact metadata, Play/Resume, favorite/watchlist, and Details actions. The feed virtualizes to the current block plus one neighbor on either side and uses measured spacers, a 600px intersection margin, lazy rail images, and explicit spotlight background release when blocks leave the render window.
- Spotlight/feed blocks use a three-block render window with measured-height placeholders, a 600px observer margin, lazy rail images, and image clearing when offscreen spotlights unmount; TV directional navigation can move between spotlight actions and the next rail.
- Mobile hamburger navigation with a left-side library drawer
- Home sections load independently and expose section-specific retry when an endpoint times out
- Library browsing, item details, and a fullscreen direct-play player with custom on-screen controls. Search lives behind a header search button: desktop and mobile expand an inline text box, while TV opens a dedicated search page with a remote-navigable on-screen keyboard on the left and live results on the right. Queries of two or more letters search as you type with stale responses ignored; shorter queries show genre and library suggestions. Result cards label their kind (Live with red highlight while airing, start time for upcoming programmes, episode codes, Series, Movie), and opening a result keeps the query, so Back returns to the search page with results intact. Results load in pages of 40 with a “Showing X of Y” summary and continue as you scroll or through an explicit “Load more results” button; leaving search cancels any request still in flight. Series opened from home, search, Live TV or a library return there with that view's position.
- Library browsing has a compact sticky counter/filter/sort bar, a right-edge `#` / `A`–`Z` scrubber with active-letter tracking and a drag bubble for title sorting, a transient scroll-position marker for other sorts, and grid/list views. The responsive filter popover contains genre/resolution/decade/watch-status controls; the grid removes page headings and uses 2:3 posters with virtualized rows. TV keeps the alphabetical rail visible on the right, and ArrowUp from the control bar focuses the active letter directly; numeric T9 keys continue to jump by title. Scrollbar chrome is hidden while native scrolling remains enabled. It requests filtered `/Items` pages of 80 and retains a sliding window of at most three pages while a fixed-height catalog canvas keeps visible rows plus a two-row buffer in the DOM. Alphabet dragging updates only the bubble until release; a jump locates the boundary with logarithmic, single-item `SortName` lookups, caches that offset for the current query, then fetches one ordinary page and positions it once. Superseded lookups and pages are cancelled, stale responses are ignored, and subsequent paging uses the same absolute catalog coordinates. This also avoids alphabet-boundary cache collisions on older plugin versions. Library posters request `maxWidth=300` at `quality=80` (list thumbnails use 160px). List rows load director names separately near the viewport so expensive full-page `People` hydration cannot block the catalog. Favorite and played state can be changed from card actions, using the server's returned state; a row that no longer matches the active watch filter leaves the list. Folders, collections and playlists list their direct children with a “Back to <parent>” control, and each library remembers its filters, sort, layout and scroll position when you return from details, a series or a child folder. Genre and decade filter options load and retry independently. Detail pages show only actions that apply to the item (Play, favorite, mark watched), show a loading note while full details arrive, list the titles for people, genres, studios and artists, and give episodes “Go to series” plus previous/next links. The player's episode drawer loads one season at a time, so very long series stay fully reachable.
- TV shows open into a continuous episode explorer: series header, sticky season navigation, and a unified scroll feed across seasons. Season deep links use `?show=<seriesId>&season=<seasonNumber>` and those parameters are removed when you leave the show; episodes are paged and neighboring seasons are prefetched while the current season plus adjacent seasons are retained in memory. On very large series, unloaded season space uses measured spacers to preserve scroll position. Delayed season and detail requests cannot move focus or replace a newer selection.
- Responsive layouts and directional-key focus movement for TV remotes. In a show, Left and Right move only between controls in the same episode; Up and Down keep the selected control across episodes and seasons. Artwork Left reaches the matching visible season navigator; moving from a season enters that season's first episode. Empty seasons keep focus on the navigator. Details and playback return to the originating view, episode control, and scroll position; episode details label their destination "Back to show". The narrow TV drawer keeps directional focus within the drawer until it closes.
- TV focus uses solid fills for keyboard keys, library chips, tabs, and primary actions without extra rings. Actions that are already lime turn white on focus. Home, search, and library cards show a rounded lime ring over the artwork, leaving titles and metadata unframed. Other controls retain visible focus indicators. Focus does not scale controls, and desktop keyboard outlines remain available.
- Poster cards keep their title and compact metadata inside a bottom artwork gradient. Badges and progress remain over the poster, while list view keeps its richer text metadata outside the thumbnail. Poster rows use the artwork ratio as their card height.
- Remote navigation reveals the full focused control, including card metadata, with 16px clearance from sticky headers and the bottom of the visible viewport. The visibility check also runs after scrolling, resizing, and virtualized content changes. Controls taller than the available space align at the top. Mouse, wheel, and touch scrolling suspend correction until keyboard navigation resumes; dialogs and the player manage their own scrolling.
- Up and Down within the home feed move to the adjacent rail or spotlight, mounting virtualized blocks before focusing their controls. Appending feed pages preserves the active block by ID. Spotlight entry scrolls immediately so a delayed animation cannot compete with focus visibility or leave the next block unmounted.
- Live TV, when the server has a Live TV library, opens into On Now, Guide, Channels, and DVR. On Now groups what is airing. The guide is a virtualized channel-and-time grid on wide screens and a Now/Next list on small screens. On TV remotes, Left/Right moves through a channel, its favorite control, and actual program cells. Left from the channel control focuses the filter. Up/Down keeps the channel/favorite role or aligns programs by time. When a row has no adjacent program, focus stays put instead of panning the timeline. At a time-window edge, the guide loads more listings before moving focus into them. Day buttons move left and right. Right from the last day focuses the channel filter, and Left from the filter returns to the last day. Up from a day button focuses the selected Live TV tab; Down enters the channel list. Up and Down on the filter change its native selection. Program details keep D-pad focus inside the sheet. Back, Escape, or Close returns focus to the program that opened it. Guide data is requested in four-hour windows. The day picker covers every day the server has guide data for, up to 14 days. Returning from a channel restores the guide's day, filter, time window, loaded channels and the tuned channel. Channel favorites are saved on the Jellyfin account; channel order is saved only in this browser and can be reset. DVR lists scheduled timers, series rules, and recordings. Timers and series rules can be edited for padding, plus new-only, any-channel, any-time and keep-up-to for series. Program sheets offer Edit, Cancel or Stop for existing recordings, and Record Series only for series programmes. Watching a channel uses the fullscreen player; HLS is played natively when the browser supports it and with hls.js otherwise.
- Browser Back and Forward move between consumer pages (home, libraries, search, details, series, Live TV, profile screens and the player); tab, season and search-term changes update the current entry instead of adding new ones.
- TV layout is chosen from, in order: `?layout=tv` or `?layout=desktop` in the URL, the "Layout on this device" setting under Playback preferences, the native wrapper's reported layout, then the browser user agent. A native wrapper bridge on its own no longer forces the TV layout.
- Overlays (Quick Connect, the mobile library drawer, Live TV program and timer sheets, library card actions, the narrow admin sidebar) move focus inside when they open, keep Tab inside, close with Escape or remote Back, make the page behind them inert, and return focus to the control that opened them. Search and library grids keep Tab moving through titles that are not yet rendered, and the guide exposes channel/program grid semantics with descriptive program names. Consumer error messages describe what to do next rather than repeating raw server responses.
- No UI component library; CSS and Preact only

Playback fills the viewport with a custom on-screen display on the direct-play stream. Episode playback shows the series and episode code in the title, and an episodes tray can jump to another episode without leaving the player. The bar includes previous and next episode, 10-second skip, play/pause, text subtitles with a timing offset, audio tracks when the browser exposes them, playback speed, picture fit, and fullscreen. The volume slider is a desktop hover control and is hidden on small screens and TV remotes. While seeking, the timeline shows a timestamp and a trickplay thumbnail when the server has generated tiles, plus intro and credits markers when media segments exist. Controls fade after a few seconds of playback. Playback start, progress about every 10 seconds, and stop are reported to the Jellyfin session, including when the page is closed, so resume position and played state stay on the server. Details offer Resume and From beginning. Negotiation uses a probed device profile and keeps the server's default audio and subtitle tracks. Audio switches that the browser cannot make locally, image subtitles, removing burned-in subtitles, quality changes and error recovery (Retry, Convert the stream, Try lower quality) request a new stream at the current position. Live streams seek within the browser's seekable window and offer Go live. The settings menu shows the actual method (direct play, remux or transcode) from this device's session. Speed (up to 3x), picture fit and volume persist per device. Picture-in-picture appears when supported, and iOS falls back to native video fullscreen. Do not use this preview as a replacement for the existing web UI.

## Develop

Requires Node.js 22.18+ and npm (`package.json` `engines`; CI and the Docker image use Node 24). The test suite imports the TypeScript sources directly, relying on Node's built-in type stripping (on by default from 22.18) and synchronous `module.registerHooks` to resolve extensionless imports, so older runtimes fail before any test runs. CI runs `npx tsc --noEmit` and `npm test` in the `ui-next` job of `.github/workflows/test.yaml`; the Docker `ui-next-build` stage runs `npm test` before `npm run build`.

Build identity: set `UI_NEXT_BUILD` (the Docker workflow passes the commit SHA) when building. The revision is embedded in the bundle, shown in the profile menu, sent to Jellyfin as the client version (`0.1.0+<sha>`), and written to `dist/build.json` (`{ revision, builtAt }`). After sign-in the app fetches `build.json` with `no-store`; when the served revision differs from the running bundle it shows a Reload notice, so a stale cached bundle is not mistaken for a server regression. To verify a deployment, compare the `build.json` served next to UI Next's `index.html` (or the profile menu) with the image's commit.

```sh
npm install
npm run dev
```

After installing dependencies, you can also start the dev server in VS Code with **Tasks: Run Task → start-ui-next-dev**.

For a development-only backend picker, run `npm run dev:debug` and open the displayed dev-site address ending in `/debug.html`. Enter the Jellyfin base URL (for example `http://localhost:8096` or `https://media.example.net`). The launcher opens the app with the backend prefilled and the app returns to its normal URL after successful sign-in. `?server=...` can also be supplied directly to the app URL. The debug page is excluded from production builds.

To route the app's standard API proxy to a local backend, set the proxy target when starting Vite:

```sh
JELLYFIN_BACKEND_URL=https://media.example.net npm run dev:debug
```

To set the Jellyfin server for the app and skip entering its address on the sign-in screen, provide `VITE_JELLYFIN_SERVER_URL` when starting the dev server:

```sh
VITE_JELLYFIN_SERVER_URL=https://media.example.net npm run dev
```

This value prefills all sign-in flows (including SSO and Quick Connect), hides the editable server field, and is also used as the Vite API proxy target unless `JELLYFIN_BACKEND_URL` is set. Without it, the app keeps its normal saved-server and login-screen behavior. If an existing saved session belongs to a different server, it is not reused.

Vite proxies selected Jellyfin API paths to `http://localhost:8096` for local development. Change those targets in `vite.config.ts` when running the local server elsewhere. The development-only SSO probe checks the backend selected in `/debug.html` through Vite, so SSO availability detection does not require CORS. The probe only contacts the proxy backend (`JELLYFIN_BACKEND_URL` or `VITE_JELLYFIN_SERVER_URL`) plus origins listed in the comma-separated `UI_NEXT_PROBE_ALLOWED_ORIGINS`, and only answers requests from this machine. `npm run dev`, `npm run dev:debug` and `npm run preview` listen on localhost; use `npm run dev:lan` to expose the dev server to other devices (for TV testing), which also lets those devices use the probe. Login and Quick Connect requests use the entered server URL directly; a different-origin backend must allow the dev UI origin in Jellyfin CORS settings for those flows. Production use requires HTTPS except when the UI and server share an origin or for localhost development.

For HTTP backend testing, use the development server only. The app displays a warning because HTTP sends credentials and tokens without transport encryption. Use HTTPS for a real server. Cross-origin backends must allow the dev UI origin in Jellyfin CORS settings.

```sh
npm run build
npm run preview
```

The build is static and is emitted to `dist/`. The Docker workflow's manual `web_ui=ui-next` choice publishes it at `/web` with the `ui-next-test` and versioned `ui-next-test-<JELLYFIN_VERSION>` tags. It does not update the standard version tag or `latest`. The test build hides links to the classic dashboard and Metadata manager. Wrapper launch behavior, media playback integration, older TV engines, and performance on physical devices still need testing.

Sign-in screens focus the first available control automatically. Up/Down moves between fields and buttons on both desktop keyboards and TV remotes; Left/Right keeps its text-editing behavior inside inputs. Enter activates buttons or submits the form. Another user opens sign-in options on desktop and Quick Connect on TVs; remembered profiles requiring credentials open the password form with the username filled in. During user switching, **Choose a profile** returns to the picker. Remote Back/Escape returns first to sign-in options, then to the picker. TV sign-in controls are enlarged and all sign-in controls have visible focus outlines. Sign-in uses a wide two-column layout with instructions beside the controls, stacking vertically on smaller screens. Quick Connect displays a large code and step-by-step approval instructions; sign-in methods use large labeled buttons, and unavailable Quick Connect is disabled. Password sign-in has larger fields and concise user-facing errors.

## Security notes

- Passwords are sent directly to the configured Jellyfin server and cleared after sign-in; they are not stored.
- The selected server, Jellyfin access token, user, and server ID are stored in `localStorage` so the login survives browser restarts; sign-out revokes the current token and records a signed-out marker so the revoked session is not restored. Earlier `sessionStorage` sessions are migrated once.
- Up to eight remembered user sessions per server are stored locally to support device-local user switching. **Switch user** keeps the old server token valid; **Sign out** revokes the current token and removes it from remembered users. Anyone with access to this browser profile can use remembered sessions, so clear browser storage on shared or untrusted devices. A remembered token is reused only for the server the current account uses and only if it passes the same address checks as the active session; otherwise the password form opens. When a token is rejected, only that token is forgotten.
- All tabs of UI Next in one browser share one signed-in session: signing in or switching user in one tab switches the others, and signing out in one tab signs the others out. A tab never removes a stored session that belongs to a newer sign-in.
- Classic dashboard links hand the current account to Jellyfin Web when it runs on the same origin as UI Next. On a different origin the links are labelled "separate sign-in", because Jellyfin Web keeps its own credentials there.
- A generated device ID is stored in `localStorage` and reused on later launches. If browser storage is blocked, the app uses one stable in-memory ID for the current page session.
- When an authenticated API request returns HTTP 401, UI Next clears the rejected session and its remembered token, then returns to sign-in with a session-expired message. HTTP 403, server errors, and network failures do not sign you out. Jellyfin revokes previous tokens when the same user signs in again with the same device ID, which can invalidate another open tab. SSO creates a Jellyfin token; UI Next does not hold an OIDC refresh token, so recovery requires another sign-in.
- Server addresses must use HTTPS, except localhost during development.
- Jellyfin API, image, login, and Quick Connect requests use the modern `Authorization: MediaBrowser ...` header. The direct-play video element uses Jellyfin's `api_key` query parameter because native media elements cannot attach custom authorization headers; playback URLs are sensitive and should not be copied or shared.
- UI Next probes `/sso/config` and `/QuickConnect/Enabled` on the selected server. **Continue with SSO** is shown only on non-TV clients when SSO is enabled; **Continue with Quick Access** starts Jellyfin Quick Connect, which must be approved from another signed-in device. TV web wrappers start on Quick Access and do not offer SSO. Username/password sign-in remains available as a fallback, and `?local=true` opens that route directly. UI Next marks a same-origin SSO attempt in `sessionStorage`. When the Jellyfin callback returns to `/web/`, UI Next accepts only the fresh same-origin credentials written during that attempt, validates the user through `/Users/{id}` and the server through `/System/Info/Public`, then stores its own session. The callback writes hyphenated user GUIDs, while Jellyfin's JSON API returns compact GUIDs. UI Next compares their GUID values and saves the API's user ID. Stale, mismatched-origin, or incomplete credentials do not create a UI Next session. Cross-origin login and Quick Connect requests require Jellyfin CORS to allow the UI origin.
- The profile menu offers server-backed Quick Connect authorization, playback and subtitle user preferences, the Pgsql taste profile, remembered-user switching, sign-out, and admin dashboard links; there is no generic Profile link. Quick Connect opens in a modal; TVs see only Switch user and Sign out. Playback/subtitle/taste screens make cross-origin API calls and require Jellyfin CORS to allow the UI origin.

## Compatibility and current gaps

Vite emits a modern bundle plus a syntax-transpiled legacy bundle (currently targeting Chrome 38+, Safari 10+, and Firefox 45+), with the legacy bundle selected by `@vitejs/plugin-legacy`. That is a best-effort web-engine target, not a guarantee for every TV browser. The TV layout supports directional arrows, common Back key codes, and basic media keys; it does not yet consume wrapper-specific JavaScript bridges or Jellyfin's registered device playback profile. Older webOS/Tizen models must be tested in their actual browser/wrapper. The `ui-next` client name/device identity is distinct from Jellyfin Web, so wrappers that special-case the existing client identity or inject native-shell APIs need explicit integration work.

The player fills the viewport with a custom on-screen display on a direct stream: series and episode titles, an episode tray, previous and next episode, text subtitles, playback speed, trickplay thumbnails, and intro or credits markers when the server provides them. It reports playback start, progress, and stop to the signed-in Jellyfin session. Live TV HLS plays in the video element when the browser can play it, and through hls.js when it cannot. It negotiates with a probed device profile, renegotiates at the current position for track, quality and recovery changes, and reports playback stops as saved only when the server acknowledges them. Device-local quality limits (bitrate, resolution, audio channels, HLS container) are stored in this browser under Playback preferences. Cross-origin deployments must list the UI origin in Jellyfin's CORS hosts, because the video element loads media and caption tracks with `crossOrigin="anonymous"`. Wrapper compatibility should be considered unverified until these are implemented and tested on named target wrappers/devices.
