# Features

Operator-facing map of capabilities in this fork: what you get, how to configure it, and which plugins/patches implement it. Env-var tables for Postgres, cache, and SSO remain authoritative in the [README](../README.md).

## UI Next preview

**What:** Experimental standalone responsive Jellyfin client with lightweight Preact rendering, local sign-in, detected OIDC SSO availability, TV Quick Connect, home/library browsing, search, item details, and a fullscreen direct-play player with series and episode context, an episode tray, text subtitles, playback speed, trickplay thumbnails, intro or credits markers when the server has them, and Jellyfin session playback reporting.

**Native playback:** In the official Jellyfin Android app, when ExoPlayer is enabled, supported video items hand off to the app's native full-screen player before UI Next negotiates a browser stream. The bridge verifies the same server and user against Jellyfin, then acknowledges readiness before UI Next calls `NativePlayer.loadPlayer()`. Jellyfin Android owns stream negotiation and playback reporting during that handoff; UI Next's OSD is replaced by the app's controls. Item order, start index, resume position and bitrate cap are passed through `NativePlayer`. If the bridge is absent, the account does not match, or ExoPlayer is disabled, UI Next uses its browser player. On webOS, UI Next keeps its HTML `<video>` player, which uses the TV's native media pipeline when supported and falls back to Hls.js for HLS. The Android app's repeat mode and UI Next subtitle appearance settings do not transfer to the native screen.

Android handoff requires a Jellyfin Android build that includes the companion `NativePlayer.syncSession` bridge. Unmodified app releases do not expose that method, so UI Next uses its browser player.

The Docker workflow can publish UI Next as an opt-in test image at `/web`. The test tags are `ui-next-test` and `ui-next-test-<JELLYFIN_VERSION>`; the regular version and `latest` tags continue to use the classic web UI. See [README: Early UI Next test image](../README.md#early-ui-next-test-image).

When the server allowlists the UI address in `JELLYFIN_SSO_UI_RETURN_URLS` (see [README: SSO configuration](../README.md#configuration)), UI Next signs in by one-time code: the callback returns to UI Next with a single-use code that only the starting tab can redeem, so separate UI origins and custom base paths work. Otherwise, for same-origin SSO, UI Next marks the sign-in attempt, then accepts the fresh Jellyfin Web credentials written by the [server callback](patches.md#jellyfin_ssopatch). Before saving its own session, it checks the token's owner through `/Users/Me` and the server through `/System/Info/Public`. Remembered-user switching uses the same `/Users/Me` owner check. If the SSO availability check fails, the sign-in screen offers Retry. A wrong username or password (HTTP 401/403) shows a credentials message; other failures show the server's error. User ID validation accepts equivalent hyphenated callback GUIDs and compact API GUIDs. Different user IDs still fail validation. It ignores stale, incomplete, or different-origin credentials.

If an authenticated API request returns HTTP 401, UI Next removes the rejected session and remembered token, then opens sign-in with a session-expired message. Permission errors, server errors, and network failures preserve the session. See the [UI Next security notes](../ui-next/README.md#security-notes) for same-device token revocation and SSO recovery.

Library browsing has a compact sticky counter/filter/sort bar (genre, resolution, decade, watch status), a right-edge alphabetical rail with a drag bubble on desktop/mobile, card badges for 4K/HDR/Dolby Vision or a short audio format, and Grid/List views. TV keeps the edge rail visible; ArrowUp from the controls focuses the active letter directly, and numeric T9 keys also jump by title. Dragging commits on release; cancellable single-item `SortName` probes locate an absolute offset without relying on alphabet suffix counts, then one page replaces the window before the viewport moves. Large libraries use filtered `/Items` requests of 80 and retain at most three pages, with a full-catalog-height virtual canvas and a two-row DOM buffer. Posters request `maxWidth=300` and `quality=80` (list thumbnails use 160px); list director names load separately near the viewport. Favorite and played actions update Jellyfin userdata.

TV shows open into a continuous season/episode feed with synchronized desktop/mobile season navigation, `?show=<seriesId>&season=<seasonNumber>` deep links that are removed when leaving the show, `?item=<itemId>` deep links that open a title's details and are removed once it opens, paginated episodes, adjacent-season prefetch, bounded episode-list retention, and measured spacers to preserve scroll positions for unloaded seasons. TV remotes move within an episode with Left/Right and preserve the chosen control with Up/Down across episodes and seasons. The visible season navigator handles the row boundary and unloaded or empty seasons; focus returns to the same episode and scroll position after details or playback. Superseded season navigation and detail responses cannot change focus or replace a newer selection. Home leads with a Netflix-style, user-controlled hero carousel combining Jellyfin `Movies/Recommendations` and the fork’s taste-ranked Movie/Series “For You” feeds. The hero requests backdrop images with poster fallback and uses title Logo artwork when available (text otherwise); when all recommendation feeds are empty or unavailable, it shuffles latest media for the hero. Mobile library navigation uses a hamburger-triggered left flyout that keeps TV remote focus within the drawer. Home sections load independently, so a slow endpoint does not hide successful sections; failed sections show a retry action. A Live TV library opens On Now, a virtualized guide (Now/Next on small screens), Channels, and DVR. On TV remotes, Left/Right moves through each channel, its favorite control, and program cells. Left from the channel control focuses the channel filter. Up/Down preserves the channel/favorite role or aligns programs by time. When a row has no adjacent program, focus stays put instead of panning the timeline. At a time-window edge, the guide loads more listings before moving focus into them. Day buttons move left and right. Right from the last day focuses the channel filter, and Left from the filter returns to the last day. Up from a day button focuses the selected Live TV tab; Down enters the channel list. Up and Down on the filter change its native selection. The program details sheet contains D-pad focus. Back, Escape, or Close restores focus to the program that opened it. Guide requests stay in four-hour windows, favorites are stored on the user account, channel order stays in the browser, and live HLS plays natively or through hls.js when the browser cannot play the stream itself.

**Where:** [`ui-next/`](../ui-next/) is the client source. The `ui-next-test` target in [`docker/Dockerfile`](../docker/Dockerfile) packages it independently of the upstream `jellyfin-web/` submodule.

**TV user switching:** Switch User opens a centered “Who's watching?” grid with large colored profile tiles and an another-user sign-in tile. The top navigation and visible Back button are hidden. The current profile receives initial focus; keyboard and remote arrows move between tiles, and Back/Escape returns to the previous screen. Tiles show the current user or whether a remembered profile needs sign-in, wrap on smaller screens, and enlarge for TV clients. Another user opens sign-in options on desktop and Quick Connect on TVs. Sign-in screens set initial focus and support Up/Down between inputs and buttons in all browsers, while Left/Right edits text. Choose a profile returns to the picker; remote Back/Escape returns through sign-in options to the picker. TV sign-in controls are enlarged. Sign-in uses a wide two-column layout with instructions beside the controls, stacking vertically on smaller screens. Quick Connect displays a large code and step-by-step approval instructions; sign-in methods use large labeled buttons, and unavailable Quick Connect is disabled. Password sign-in has larger fields and concise user-facing errors.

**Playlists, Favorites and reload:** Playlists page their entries 200 at a time; Play all and Shuffle fetch the rest (up to 5,000) before queuing. Add to playlist (existing or new) is available from details, library card menus and the bulk bar. Item details keep Play/Resume, favorite, watched and episode actions in the main row and place Download, Share, Add to collection, Add to playlist, metadata management and Delete behind a **More** menu; **Share** copies a `?item=<id>` link that opens the title in UI Next. Playlists the server reports as editable offer rename, move up/down and remove; shared read-only playlists stay read-only, and sharing is managed in Jellyfin Web. Favorites groups load 24 at a time with Show more. Reloading the browser reopens the current page (a player reopens its details) instead of Home.

**Home feed:** The home page combines the personalized hero with library chips and an interleaved feed of rails and cinematic spotlights. Rail sources include resume, true Next Up from `/Shows/NextUp`, latest, On Now, Jellyfin recommendation groups, and paginated library exploration so the feed continues when recommendation groups are empty. The Next Up request explicitly disables resumable-only results and refreshes after reported playback. Spotlights are generated from available BoxSet collection metadata, director recommendation groups with at least four titles, rated-8+ unwatched movies older than six months, and resumed TV episodes. The feed virtualizes around the current block and neighboring blocks to constrain DOM and image memory.

TV focus uses solid fills on keyboard keys, library chips, tabs, and primary actions. Already-lime actions turn white when focused. Home, search, and library cards draw a rounded lime ring above their artwork without framing the title or metadata. Focus does not scale controls. See the [UI Next README](../ui-next/README.md#current-prototype) for the focus treatments.

Poster cards place the title and compact metadata in a bottom artwork gradient. Badges and progress stay on the poster. List view retains its richer metadata beside the thumbnail. Poster grid rows use the artwork ratio for their height.

Remote navigation keeps the entire focused control visible below sticky headers and above the viewport's bottom edge, with 16px clearance. The same check handles later scroll, resize, and virtualized-content changes. Oversized controls align at the top. Pointer scrolling suspends correction, and dialogs and the player retain their own scroll handling.

Up and Down in the home feed mount and focus the adjacent rail or spotlight. Appending feed pages preserves the active block by ID. Spotlight entry scrolls immediately rather than animating after focus has moved.

**Profile menu:** The menu opens modal Quick Connect authorization and links to playback/subtitle/control preferences, the Home screen layout, an Account screen (change or set your own password, upload or remove your profile image), the Pgsql taste profile, remembered-user switching, sign-out, and for administrators the admin workspace, its native Metadata manager, and the classic dashboard. TV menus show Playback, Subtitles, Controls, Display, Home screen, Switch User and Sign Out. Controls are stored per device: game-controller navigation (D-pad or left stick moves, A selects, B goes back) and smooth scrolling. Local sign-in lists the server's public users (passwordless users sign in with one press) and offers Forgot password?, which follows Jellyfin's PIN reset flow. Up to eight remembered sessions are stored per server in the browser; Switch User retains a reusable token, while Sign Out revokes the active token and leaves that profile remembered without a token. See the UI Next [security notes](../ui-next/README.md#security-notes) before using saved sessions on a shared device.

**Language, theme and display:** UI Next is translated with Jellyfin Web's own strings wherever the English text matches; messages unique to UI Next fall back to English. The profile menu's Display screen picks the language (shared with Jellyfin Web through the per-user `<userId>-language` browser key), a dark, light or system-matched theme, text size (90–130 %) and reduced motion. Arabic, Persian, Urdu and Hebrew use a right-to-left layout; the player, seek bar and Live TV guide keep a left-to-right time axis, and the player stays dark in every theme. See [UI Next README: Translations](../ui-next/README.md#translations).

**Music playback:** UI Next has a dedicated music player that keeps playing while you browse: a mini-player bar expands to a Now Playing view with seek, shuffle, repeat, volume and an editable queue. Songs, albums, artists, genres and song playlists offer Play, Shuffle, Instant Mix, Play next and Add to queue (also from library cards). Tracks stream from Jellyfin's `/Audio` endpoint with an audio device profile; the next track preloads for near-gapless changes, and each device can set volume levelling from Jellyfin's `NormalizationGain` (album or track), a crossfade of up to 12 seconds, and gapless album playback. Playback is reported to the Jellyfin session with its queue, appears in browser or native-wrapper media controls, pauses when a video starts and stops on sign-out. It uses stock Jellyfin APIs (PlaybackInfo, audio streaming, Instant Mix); no server patch is involved. Caveats are in [known issues](known-issues.md#operational-caveats-this-image).

**Metadata editing:** On desktop and mobile (not TV), item details offer administrators Edit metadata, Images (upload, delete, reorder backdrops, online image search), Identify (provider search and apply) and Refresh metadata (scan, fill missing or replace all). Users with Jellyfin's subtitle- or lyric-management permission get Subtitles (search, download, upload) on videos or Lyrics (search, download, upload, delete) on songs; only administrators delete external subtitles. Saves send only edited fields onto a freshly read item. Online thumbnails load from provider hosts without a referrer, and uploads are type- and size-checked; see the UI Next [security notes](../ui-next/README.md#security-notes).

**Admin workspace:** Administrator-only entry from the profile menu opens a shared-shell operations area with overview, Users & access, Libraries, Playback, Live TV, Metadata, Recommendations, Infrastructure, Activity, and System sections. The Metadata section browses each library by folder (with type filter and search), flags locked items and items without external IDs, and opens the item metadata editors for any row; its Display, Metadata and NFO tabs edit library display options, the date-added source, default metadata language/country, generated chapters, chapter image resolution and NFO output, saving only changed fields. It consumes the authenticated Jellyfin APIs plus Pgsql cache and taste-admin stats. The Users section supports user inspection, SSO/RBAC mapping editing, and the server-side chunked Emby userdata preview/import workflow. Libraries expose inventory/counts and scan/refresh actions, plus an editor for existing libraries: rename, add or remove folders, enable/disable, metadata language and country, ordered metadata/image fetchers per item type, local metadata readers and savers, real-time monitoring, embedded-title, chapter and trickplay extraction, subtitle download languages and providers, and lyric/media-segment providers. Folder changes apply immediately; other settings save as one document that keeps options the editor does not show; Live TV provisions tuners (add/edit/delete M3U and HDHomeRun hosts, network discovery of new HDHomeRun devices), guide providers (XMLTV path/URL with category mapping; Schedules Direct sign-in, country/postal code and lineup), per-provider tuner selection and channel mapping, and can start a guide refresh. Each channel mapping saves immediately; provider saves keep mappings and other stored fields from the latest server copy. Playback → Transcoding edits the server-wide encoding settings like Jellyfin Web's Transcoding page (hardware acceleration type, devices, decoding codecs, hardware/low-power encoding, HEVC/AV1, tone mapping, encoder quality, audio downmix, paths, throttling and segment deletion) plus this fork's [codec fallback and parallel race](patches.md#jellyfin_z_transcode_codec_fallbackpatch) and [live-stream buffer/probe/timeout options](patches.md#jellyfin_livetv_streampatch); acceleration types and decoders FFmpeg did not detect (via [`jellyfin_hwa_capabilities`](patches.md#jellyfin_hwa_capabilitiespatch)) are disabled or flagged. Playback and Overview show live sessions with Pause/Resume, Message and Stop for clients that accept remote control, plus recorded playback-method/client aggregates; Infrastructure shows Pgsql cache counters, tasks, devices, a tailing server log viewer, and encoder/storage data when the server exposes it. Users can be given a new password by an administrator (clearing the password is offered only for non-administrators). Deleting, demoting or disabling the last enabled administrator is refused by the server under one lock with a database recount, so concurrent changes cannot remove every administrator ([`jellyfin_zz_last_admin_invariant`](patches.md#jellyfin_zz_last_admin_invariantpatch)); UI Next reports it as "There must be at least one administrator." Plugin pages (PostgreSQL, TMDb, Seerr and a generic editor for other plugins) save only after their own configuration loaded, mask secret fields, warn before leaving with unsaved changes, and the PostgreSQL page flags settings overridden by `Pgsql_*` environment variables. The Plugins section manages the plugin lifecycle through Jellyfin's package APIs: installed plugins show available updates; a catalog of the enabled repositories offers any listed version to install, update or downgrade (downgrades and plugins from repositories other than `repo.jellyfin.org` need confirmation); installed plugins can be uninstalled (not bundled ones, and never the PostgreSQL provider, which also cannot be disabled there); plugin repositories can be added, enabled/disabled and removed; and a banner offers a server restart once changes are pending. Failed reads are reported per resource instead of appearing as empty or unconfigured. Destructive server actions and session playback stops require confirmation. Values unavailable from the current APIs are omitted or labelled unavailable; no storage, queue, or telemetry values are fabricated. Server settings are edited in place and save only the changed fields onto a freshly read configuration document: general (name, language, cache/metadata paths, Quick Connect, scan and image concurrency), networking (LAN, bind addresses, IP families, discovery, remote IP filter, HTTPS and certificate), branding, logging (slow responses, log and activity retention), playback resume/streaming/trickplay and DVR recording paths, padding and post-processing. Users can be renamed and have unrated-content blocks, access schedules, channel and device allowlists, authentication/password-reset providers and the full permission set; the guided SSO/RBAC form lists every permission. Scheduled tasks have a trigger editor, devices a custom name and per-device playback overrides (via the [device playback options patch](patches.md#jellyfin_zzzzz_device_playback_optionspatch)), backups choose their content, can inspect an archive's manifest and wait for the server after a restore, and the live log can be downloaded or copied. Playback statistics add per-user, most-played, day×hour and recent-playback views, the admin Recordings tab manages in-progress recordings and series rules, and Recommendations show evaluation history. The UI Next sign-in screen shows the server's login disclaimer (as plain text), splash screen and custom CSS. On [active-standby HA](#active-standby-ha-opt-in) servers the top bar shows the instance's HA role and leader epoch, and the Overview adds a High availability card with readiness and failovers seen this session. Some advanced controls (user lifecycle bulk actions, database internals, Seerr queue, and Live TV multiview usage) are not exposed by the current admin APIs.

**How:** Run `npm install && npm run dev` from `ui-next/`; see its [README](../ui-next/README.md) for local proxy and security details. UI Next probes `/sso/config` and offers the server's SSO redirect when enabled; the existing callback completes into Jellyfin Web, so it does not transfer an authenticated session back to a separate debug origin. TV clients use Quick Connect when enabled. This preview is not packaged in the production image and does not replace Jellyfin Web. The player negotiates with a probed browser device profile (codec levels, HDR ranges, subtitle delivery, the [Chrome/Opera MKV guard](patches.md#jellyfin_web_chrome_mkv_directplaypatch)), resumes from the saved position, and can request a new stream at the current position for audio or subtitle changes, quality changes and error recovery. One playback session owns negotiation, reporting, and tuner cleanup across play, renegotiation, leave, route, and account changes; tuner-backed streams fall back to `POST /LiveStreams/Close` only when stop-report delivery fails. Video playback publishes browser MediaSession metadata and supports play, pause, seek, previous, next and Stop from OS/media controls; Stop leaves the player and preserves the current resume position. Device-local quality limits and per-type segment skipping (show a Skip button, skip automatically or ignore intros, credits, recaps, previews and commercials) live under Playback preferences; Subtitle preferences hold caption appearance (size, font, colour, edge, position) and whether styled ASS/SSA or all subtitles are burned in. The player offers alternate versions (remembered for later episodes of the series), chapter navigation and markers, and an optional secondary subtitle track. Live TV DVR timers and series rules can be edited from UI Next. Search pages through all results, libraries keep their filters and position across details and nested folders, a Favorites page groups favorites from every library (titles, artists and people), search also lists matching people, artists, genres and studios, Home can be reordered and trimmed per user from the profile menu's Home screen page (with Continue listening/reading, taste-profile For You rows with match tiers, and optional per-library Latest rows), libraries offer type-specific modes (TV Shows/Suggestions/Upcoming/Episodes, music Albums/Suggestions/Album artists/Artists/Songs, photo and home-video Folders/Photos/Videos, books, music videos), a Search-this-library field, combinable filters (watch state plus Favorites, multiple genres, decades, tags and parental ratings, series status, missing/unaired episodes, subtitle/trailer/extras flags), extra sorts (recently played, most played, parental rating, random) and Thumb/Banner layouts, and detail pages link cast, crew, genres, studios, tags and artists to their titles and episodes to their series and neighbours. Crew chips separate the name from the role (`Name · Role`), and cast/crew, genres/studios, similar titles and the paged title list render in a full-width section below the capped title hero so posters and chips are not squeezed into the hero column. Details also show official and critic ratings, tagline, provider links and compact media tags (4K/HD/SD, HDR, CC) instead of the full stream listing; similar titles and collection membership; trailers, special features and additional parts; album tracks by disc (with lyrics), playlist entries, photo albums with a full-screen viewer and slideshow, and collection members. Download, Share (a `?item=` UI Next link without credentials), Add to collection and a two-step Delete appear only when the server's per-item flags and the user's policy allow them; series and season headers can be favourited or marked played. Library cards offer Delete and, inside a collection, Remove from collection under the same rules. A library Select mode applies Mark played/unplayed, Favorite/Unfavorite, Add to queue, Add to collection and a two-step Delete to up to 200 titles, four requests at a time, skipping titles the server does not allow and reporting partial failures. When a title ends the player shows a 10-second Up next card for the next queued title or, unless the account's *Automatically play the next episode* preference is off, the next episode. A per-session video queue offers Play next / Add to queue from library cards, Play all / Shuffle on playlists and collections, and queue previous/next, shuffle and repeat in the player. Browser Back/Forward follows consumer navigation, overlays manage focus as modal dialogs, and the TV layout can be forced with `?layout=tv` / `?layout=desktop` or the device's Playback preferences when a wrapper or browser is misdetected. Each build records its revision (`UI_NEXT_BUILD`, the commit SHA in the Docker workflow) in the profile menu, the Jellyfin client version and a served `build.json`; a tab running an older bundle than the one being served shows a Reload notice (see the [UI Next README](../ui-next/README.md#develop)). The `ui-next` CI job and the image build run the UI Next test suite. Native wrappers that inject Jellyfin Web's `NativeShell` bridge get the core app-host contract: the wrapper's device and app identity, `supports()`-gated Download, provider links, uploads and fullscreen, Client settings / Download manager / Exit app menu entries, the host's device profile, sign-in/out notifications, and media session and volume updates (see [UI Next compatibility](../ui-next/README.md#compatibility-and-current-gaps)). Native player plugins and webOS/Tizen-specific bridges are not implemented, and wrapper and older TV browser support require device testing before rollout.

UI Next keeps an accepted playback source active while a replacement is prepared. A failed replacement leaves the source playing. Progress, seeking, and resume use the same item timeline, including progressive conversion offsets. Session reports are ordered so the old stop completes before a replacement start. Live stream replacements can retain the tuner; abandoned negotiations release their resources. Embedded subtitle delivery uses native tracks when available and renegotiates otherwise.

## PostgreSQL database provider

**What:** Jellyfin stores its system database in PostgreSQL instead of SQLite.

**Where:** [`Jellyfin.Plugin.Pgsql`](../Jellyfin.Plugin.Pgsql/), Docker entrypoint `POSTGRES_*` wiring, [`docker/database.xml`](../docker/database.xml).

**How:** The plugin registers as a custom database provider. Images set connection parameters from environment variables (`POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, optional SSL). `Pgsql_COMMAND_TIMEOUT` (default `90`) raises Npgsql’s command timeout for heavy library queries.

**Related:** SQLite→PG migration in [README](../README.md#migrating-from-sqlite-to-postgresql); inherited scale caveats in [known issues](known-issues.md).

## Query cache and optimised Latest and Resume

**What:** Cache home Latest/Resume ID lists and stable library browse `/Items` pages; optionally replace Latest queries with PostgreSQL `DISTINCT ON` variants. Supported Resume pages use a candidate-first selector driven by the user's positive playback-progress rows, including total counts before paging.

**Where:** [`Jellyfin.Plugin.Pgsql/Query/`](../Jellyfin.Plugin.Pgsql/Query/); toggles `Pgsql_CACHE_*`, `Pgsql_PG_OPTIMIZE_*`, `REDIS_CONNECTION_STRING` ([README](../README.md#query-cache-and-optimisation-optional-experimental)).

**How:** Cache keys are per user and per view (never shared across users). Alphabet prefix/lower/upper boundaries are included so different letter queries cannot share IDs or counts. Failures fall back to stock Jellyfin queries. Redis uses a shared persistent multiplexer with background PING health: request paths only touch Redis when status is `Ready`; `Unknown`/`Unavailable` skip immediately to the in-process memory fallback (no repeated SyncTimeout wait). Cache operations default to a bounded 250 ms deadline (`Pgsql_REDIS_OPERATION_TIMEOUT_MS`) so brief local stalls do not cause the 100 ms false-unhealthy flapping seen under load. Default Latest TTL is 120s; browse pages default to 60s (`Pgsql_CACHE_BROWSE_TTL`). Browse cache stores `(TotalRecordCount, ids[])` for recursive SortName-style library pages.

**Resume selection:** `Query/PgResumeQuery.cs` reuses core access-filter translation without its generic resumability expression. It aggregates progress once, compares candidate versions, and loads item details and collections by the selected IDs. `Pgsql_PG_OPTIMIZE_RESUME` works even with caching disabled. Resume keys include owner/version options, descendant scope, and explicit rating/tag restrictions. In-scope folder candidates, search, alternate ordering, and unsupported filters fall back to core. Configure the switch in the [README query optimisation section](../README.md#query-cache-and-optimisation-optional-experimental); UI Next admin also exposes the toggle with its environment override. Existing server support comes from the [query split patch](patches.md#jellyfin_query_split_userdatapatch) and [home API performance patch](patches.md#jellyfin_home_api_performancepatch); this selector adds no server patch.

**Patches that help home/query load:** [`jellyfin_home_api_performance`](patches.md#jellyfin_home_api_performancepatch), [`jellyfin_unoptimized_query_fixes`](patches.md#jellyfin_unoptimized_query_fixespatch), [`jellyfin_query_split_userdata`](patches.md#jellyfin_query_split_userdatapatch), [`jellyfin_z_items_browse_perf`](patches.md#jellyfin_z_items_browse_perfpatch), [`jellyfin_latest_tv_always_series`](patches.md#jellyfin_latest_tv_always_seriespatch), [`jellyfin_zzz_byname_access_semijoin`](patches.md#jellyfin_zzz_byname_access_semijoinpatch), [`jellyfin_zzzz_people_query_perf`](patches.md#jellyfin_zzzz_people_query_perfpatch). Descendant-query memory fixes are stock Jellyfin as of v12.0-rc6 ([jellyfin#17602](https://github.com/jellyfin/jellyfin/issues/17602)).

## Fuzzy search (PostgreSQL)

**What:** Server-side fuzzy / franchise-oriented search via the plugin provider; core SQL search provider is disabled when the plugin is present so results do not double-count.

**Where:** [`Jellyfin.Plugin.Pgsql/Search/`](../Jellyfin.Plugin.Pgsql/Search/); patches [`jellyfin_search_performance`](patches.md#jellyfin_search_performancepatch), [`jellyfin_disable_sql_search_provider`](patches.md#jellyfin_disable_sql_search_providerpatch); web infinite scroll on search ([`jellyfin_web_user_search_infinite_scroll`](patches.md#jellyfin_web_user_search_infinite_scrollpatch)).

**How:** Plugin registers an `ISearchProvider`. ApplicationHost prefers PostgreSQL similarity for “Similar” and excludes `SqlSearchProvider` from search parts. Fuzzy title matching uses only the indexable pg_trgm `<%` operator (`jellyfin_word_similar`) with a per-transaction similarity threshold so `IX_BaseItems_CleanName_trgm` can be used — Levenshtein and function-form `similarity()` are not OR’d into the same filter (those force a sequential scan). Total-count is computed from the page when it is not full; `CountAsync` of the union runs only when the page is full and the client asked for a total. Genre/tag `ILIKE` goes through `jellyfin_ilike`, which inlines to `haystack ILIKE pattern` so GIN trigram indexes on OriginalTitle / Genres / Tags can be used. More Like This scores franchise titles the same way (one batched `<%` / `ILIKE` pass instead of a `word_similarity()` scan per source) and hides already-played candidates with a `UserData` lookup on the short candidate list rather than the rc5 folder-descendant `IsPlayed` SQL.

**People listings:** `/Persons` collapse (one row per provider key or lowercased name) lives in [`jellyfin_zz_person_provider_identity`](patches.md#jellyfin_zz_person_provider_identitypatch). Name-contains search and batched `HasSegments` on media-source builds are in [`jellyfin_zzzz_people_query_perf`](patches.md#jellyfin_zzzz_people_query_perfpatch).

## Single Sign-On (OIDC) and RBAC

**What:** Forced OIDC login for browsers, auto-create users, admin role from IdP groups, parental rating from birthdate claim, and per-group dashboard mappings for libraries, permissions, block-unrated types, Allowed/Blocked tags, and Live TV channel/category allowlists (exceptions when unrated Live TV is blocked).

**Where:**

## Taste profiles, For You, and taste models

**What:** Per-user taste profiles and precomputed recommendations; home “For You” section; user taste identity UI; admin shadow-eval reports for taste models. Engagement weighting uses completion-aware playback (short abandons are negatives; deep watches/favorites are positives) and For You impression logs so recommended→engage is boosted and recommended→abandon is penalized more strongly. Profiles also store year / runtime / parental bands, movie-vs-series share, writers, box-set membership, original language, and production country; live linear scoring (For You, similar, match badges) applies soft penalties outside those bands, boosts writer / collection / language / country overlap, and demotes confirmed For You skips (impressed, no later engagement, after a 14-day confirm window). Shadow neural training uses the same axes, mixes genre-matched hard catalog negatives with random ones, treats confirmed impression skips as weak negatives, and applies recency decay on labeled sample weights. Evaluation uses a time-based holdout (newest 20% of the event span), global Precision@10, per-user Mean Precision@10, and a matured For You impression→engage rate (14-day window). ROC AUC is omitted when the holdout contains only one class (catalog negatives are kept in the train window so they do not leak into eval). When `Pgsql_TASTE_NEURAL_SERVE` is on and a shadow zip loads, the **recommendations refresh task** blends 50% neural with 50% linear into stored For You rows and Because you watched/liked similar lists (up to 12 recently played + 8 liked baselines, franchise-diversified, 16 items each). `GET /Movies/Recommendations` and More Like This read those rows; a title watched after the last rebuild falls back to similarity + linear only. Match badges stay linear on the request path. Neural serving stays **off** by default.

**Where:**

- DB entities: [`jellyfin_user_taste_profiles`](patches.md#jellyfin_user_taste_profilespatch), [`jellyfin_user_taste_recommendations`](patches.md#jellyfin_user_taste_recommendationspatch), [`jellyfin_z_user_taste_recommendation_impressions`](patches.md#jellyfin_z_user_taste_recommendation_impressionspatch), [`jellyfin_zz_user_taste_because_you`](patches.md#jellyfin_zz_user_taste_because_youpatch)

### Per-device playback and transcoding options

**What:** Dashboard → Devices → Edit lets administrators override playback permissions, a maximum streaming bitrate, preferred output codec, tone mapping, audio/quality/deinterlacing, hardware decoding/encoding and codec fallback for **one registered device**. Each field inherits the server or client policy until explicitly overridden. A preferred codec only reorders codecs the client already advertised; e.g. prefer H.264 over HEVC for an SDR Android TV while keeping HEVC on other devices. Tone mapping can use BT.2390, TV color range and automatic source peak (`0`); peak `100` means 1000-nit input, not a 100-nit SDR output target.

**Where:** Server [`jellyfin_zzzzz_device_playback_options`](patches.md#jellyfin_zzzzz_device_playback_optionspatch) with SQLite schema migration, plugin `Jellyfin.Plugin.Pgsql/Migrations/20260926204250_AddDevicePlaybackOptions.cs` for PostgreSQL, web [`jellyfin_web_zzzzz_device_playback_options`](patches.md#jellyfin_web_zzzzz_device_playback_optionspatch).

**How:** Admin-only `GET /Devices/Options` and `PUT /Devices/Options/Playback` read/replace sparse settings; `{}` clears them. Existing `POST /Devices/Options` still edits the name without clearing overrides. Playback uses the authenticated access token's registered device, not a client-supplied device id; API keys do not get device overrides. Hardware/HEVC/AV1/race permissions and codec decode lists cannot exceed global settings. Effective encoding settings are cloned and pinned to an active playback job. Deleting a device in the dashboard removes its saved overrides. No extra environment variables are needed.

## Playback error messaging

**What:** Structured playback failure codes from the server and a friendlier web dialog (summary, tip, Try Again / Try with Transcoding). Mid-stream HLS failures expose intent via the `X-Playback-Error-Code` response header; pre-play failures use `PlaybackInfoResponse.errorCode` (+ optional `message`). Subtitle/audio stream changes proceed even when cleanup of the previous transcode transiently fails.

**Where:** [`jellyfin_zzz_playback_errors`](patches.md#jellyfin_zzz_playback_errorspatch) + [`jellyfin_web_zzzz_playback_errors`](patches.md#jellyfin_web_zzzz_playback_errorspatch).

**Web behaviour:** Title “Couldn't play this”; localized `PlaybackErrorFriendly.*` strings; one automatic reconnect attempt on `LiveStreamFenced` before showing the dialog.

**Client contract (mobile / third-party):**

| Phase | Source | Action |
|---|---|---|
| Pre-play | `PlaybackInfoResponse.errorCode` (PascalCase default; camelCase with `Accept: application/json; profile="CamelCase"`) | Map code to platform strings; optional `message` is English fallback only |
| Mid-play | `X-Playback-Error-Code` on failed manifest/segment HTTP responses; optional JSON `{ errorCode }` on API errors | Prefer header; fall back to generic network/server error if missing |
| `LiveStreamFenced` | 503 + code | Restart playback (web auto-retries once) |
| `TranscodeFailed` / `TranscodeNotAllowed` | 500 / 403 | Suggest retry or ask admin about transcoding permissions |
| `NotAllowed` | 403 at PlaybackInfo | Policy denial — contact admin |

Extend `@jellyfin/sdk` `PlaybackErrorCode` when bumping Jellyfin tags (new enum values: `TranscodeFailed`, `TranscodeNotAllowed`, `StreamUnavailable`, `LiveStreamFenced`).

## Active-standby HA (opt-in)

**What:** One writer at a time: PostgreSQL advisory lock, leader-only library watchers/scheduled tasks/recording timers, `/health/ready`, `X-Jellyfin-Leader-Epoch` / `X-Jellyfin-Ha-Role` headers, Live TV `LiveStreamFenced` 503, flush coalesced progress on shutdown, optional Redis progress overlay.

**Where:** Plugin [`Jellyfin.Plugin.Pgsql/Ha/`](../Jellyfin.Plugin.Pgsql/Ha/); patch [`jellyfin_z_ha_leadership`](patches.md#jellyfin_z_ha_leadershippatch). Env: [README](../README.md#active-standby-ha-optional).

**How:** `Pgsql_HA_ENABLED=true`. Fail-closed until the lock is held. EF migrations take a separate blocking advisory lock so two boots cannot interleave DDL. HLS VOD already restarts ffmpeg from the requested segment; Live TV is not retuned.

**Diagnostics:** The leadership headers are exposed to cross-origin clients (`Access-Control-Expose-Headers`). Admin-only `GET /Pgsql/Stats` adds `HaEnabled`, `HaRole`, `LeaderEpoch`, `LeaderSinceUtc`, `HaHeartbeatSeconds` and `InstanceName` (host name). The UI Next admin workspace shows an "HA leader · epoch N" or red "Standby instance" chip in the top bar, and the Overview has a High availability card (role, epoch, instance, leader since, heartbeat, `/health/ready` result, failovers seen this session). Standby and not-ready raise a critical health issue; a failover observed in the last ten minutes raises a degraded one. The epoch is per process, so failover is detected from role/epoch header changes and from a different instance name or start time in stats. Single-instance servers show nothing.
