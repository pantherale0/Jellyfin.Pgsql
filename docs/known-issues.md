# Known issues and caveats

Operational and tracker notes for this fork. For benefits/drawbacks framing see [overview](overview.md).

## Experimental status

This project is **highly experimental** and maintained for personal use. Expect breakage on Jellyfin upgrades until patches and migrations are re-validated. Issues and pull requests on [pantherale0/Jellyfin.Pgsql](https://github.com/pantherale0/Jellyfin.Pgsql) are **collaborator-only**; prefer [Discussions](https://github.com/pantherale0/Jellyfin.Pgsql/discussions) for public conversation.

## Plex2Shell-focused security review

The 2026-10-21 review covered the pinned Jellyfin `v12.1` server with this fork's server patches applied, the current `ui-next` source, and the plugin endpoints used by that client. The reference was the [researcher's Plex2Shell disclosure](https://zmain.info/blog/plex2shell), linked from the [reported exploitation](https://thehackernews.com/2026/10/cisa-orders-federal-agencies-to-patch.html).

No complete unauthenticated SSRF-to-admin-token-to-server-code-execution chain was demonstrated. Jellyfin's `AuthService.Authenticate` validates token values, and configuration mutations and plugin installation require elevated authorization. The reviewed transcoding APIs resolve existing media sources rather than accepting Plex's arbitrary media `path` parameter. No confirmed matching defect was found in UI Next's playback-origin checks, external-link scheme checks, SSO return handling, or plain-text disclaimer rendering.

The review did confirm these server issues. The [media resource security patch](patches.md#jellyfin_zzzzzz_media_resource_securitypatch) fixes both.

| Severity | Finding and preconditions | Fix |
|---|---|---|
| High | `VideoAttachmentsController.GetAttachment` returned media-supplied HTML or SVG MIME types inline. A crafted media attachment must enter a scanned library, and a viewer must open its delivery URL. Before the fix, the route needed no token. Active content could run under the server's origin and access browser-stored credentials. | Require authentication and the existing user-scoped item lookup. Force download disposition and disable MIME sniffing. |
| Medium | Both `SubtitleController.GetSubtitle` routes and video attachments allowed anonymous reads when their item/source IDs were known. Subtitle lookup also ignored the signed-in user's library visibility and could trigger extraction for hidden items. | Require authentication. Resolve the subtitle's effective item ID against the authenticated user's library permissions before reading or extracting it. |

Local ASP.NET Core HTTP tests reproduced successful anonymous reads, hidden-item subtitle reads, and inline HTML responses before the fix. Afterward, the full API test project passed 159 tests, including 13 new security and delivery-URL cases. UI Next's 469 unit and fake-server tests passed. `npm audit --omit=dev --json` and the API project's NuGet vulnerability check with transitive dependencies reported no known advisories at review time.

The review used targeted static searches and manual data-flow tracing. It was not a full SAST scan, a production penetration test, or an audit of FFmpeg/native codec binaries and every third-party plugin. Embedded-font behavior was checked at the authenticated HTTP-response and delivery-URL boundaries, not on physical clients. Tests ran in Release because the installed SDK's compiler could not load the newer Roslyn analyzer required by Debug builds.

## Operational caveats (this image)

| Caveat | Detail |
|---|---|
| Cache lag | Default Latest TTL is 120s — new media can take up to that long to appear in cached Latest rows ([README](../README.md#query-cache-and-optimisation-optional-experimental)). |
| TV Latest optimisation | Plugin ports Season/Series container logic; **re-check** when syncing to new Jellyfin releases. |
| Command timeout | Stock Jellyfin’s 30s Npgsql default is tight for large remote DBs; this image defaults `Pgsql_COMMAND_TIMEOUT` to `90`. |
| Legacy Resume query and PostgreSQL JIT | A reproduced legacy Resume query spent about 25 seconds compiling 1,624 JIT functions. The candidate-first plugin selector avoids the library-wide resumability tree for supported DatePlayed-descending pages. In-scope folder candidates, search, other sorting, unsupported criteria, and recoverable failures still use core and can retain the legacy cost. Keep a database-level `jit=off` mitigation where measurement justifies it; the plugin does not change JIT settings automatically. See `Pgsql_PG_OPTIMIZE_RESUME` in the [README](../README.md#query-cache-and-optimisation-optional-experimental). |
| Custom image required | Patched server APIs and UI Next are not available if you only drop the plugin DLL into stock Jellyfin. |
| UI Next compatibility | Standard image tags serve UI Next at `/web`. Its legacy bundle targets older browsers, but no named TV or wrapper device has been verified. Test the app on the target browser before deployment. See [UI Next compatibility](../ui-next/README.md#compatibility-and-current-gaps). |
| Chrome/Opera Matroska DirectPlay | UI Next declines MKV DirectPlay for Chrome and Opera because those browsers can report Matroska support and then fail silently. Playback may transcode even when the browser reports `video/x-matroska` support. |
| UI Next browser E2E coverage | Playwright runs Chromium against a generated fake Jellyfin server and a checked-in WebM. It covers sign-in, home, library/detail browsing, playback reports, the `?layout=tv` override, dialog focus, profile-menu links, and plugin settings. An emulated webOS user agent covers TV D-pad focus, remote Back, show-detail navigation, and player controls. The suite does not verify real server behavior, SSO, Quick Connect approval, Live TV, complete admin flows, wrappers, or physical devices. See [UI Next end-to-end tests](../ui-next/README.md#end-to-end-tests). |
| UI Next Android native playback | Supported video handoff requires the official Jellyfin Android app with ExoPlayer enabled. The bridge validates the selected server and the access token's `/Users/Me` user before updating the app's saved `ApiClient`; UI Next waits for a ready acknowledgement. The native player owns controls and reporting; UI Next's repeat mode and subtitle appearance preferences are not transferred. `loadPlayer()` itself has no launch acknowledgement, so UI Next cannot detect a later native launch failure. Playback state refresh on return uses WebView focus/visibility events; hosts that emit neither may show stale local resume state until the next fetch. Validate on the target Android app/WebView version. |
| UI Next Android bridge availability | Native handoff needs the companion `jellyfin-android` `NativePlayer.syncSession` method. Upstream app releases without that method fall back to UI Next's browser player. |
| UI Next revoked sessions | Another sign-in by the same user with the same device ID revokes the previous Jellyfin token. HTTP 401 now returns UI Next to sign-in instead of leaving failed home sections with ineffective Retry buttons. UI Next has no OIDC refresh token; see its [security notes](../ui-next/README.md#security-notes). |
| SSO browser binding | The OIDC callback must arrive in the same browser and on the same host that started sign-in (a `jellyfin_sso_state` cookie), within 10 minutes. Starting sign-in from a LAN address while `JELLYFIN_SSO_OIDC_REDIRECT_URI` uses a public domain is rejected; use the redirect URI's host ([README](../README.md#single-sign-on-sso-with-rbac-via-oauth2oidc)). |
| UI Next tabs share one session | Signing in, switching user or signing out in one UI Next tab applies to every UI Next tab in that browser profile. |
| Remote trailer dependency | YouTube extractor behavior changes independently of Jellyfin. Remote trailers may stop resolving until the pinned yt-dlp release is updated. Private/authenticated/age-restricted/geo-bypassed videos are unsupported; relaying consumes server bandwidth and the old iframe is not used as fallback. Adaptive-only trailers are streamed through ffmpeg and therefore do not support byte-range seeking. |
| Server patch drift | Every upstream bump can break `git apply`; maintainers must refresh the server patch series. |
| SSO for a separate UI origin | UI Next on another origin or base path needs its address in `JELLYFIN_SSO_UI_RETURN_URLS` and the origin in Jellyfin's CORS hosts; without it UI Next uses the same-origin handoff, which cannot complete across origins ([README](../README.md#configuration)). |
| SSO redirect URI | Must be an absolute configured URI (`JELLYFIN_SSO_OIDC_REDIRECT_URI`); do not derive from `Request.Host`. |
| Credentials in older startup logs | Older images logged environment values verbatim. Current startup logging redacts credential-like names, but existing log copies remain sensitive; rotate any exposed OIDC secret, password, token, API key, private key, or connection-string credential. |
| Live TV RBAC categories | M3U `group-title` categories appear in SSO allowlists only after a guide refresh with [`jellyfin_z_livetv_rbac_allowlist`](patches.md#jellyfin_z_livetv_rbac_allowlistpatch). HDHomeRun/XMLTV-only setups typically get EPG Kids/Sports/News categories, not playlist groups. |
| Live TV client hang (Wholphin) | After open, classify from logs: `Shared=true` + high `AgeMs` (stale share), `ClearedUnreachableOrigin` (cluster-internal M3U Path stripped), or open without a following `Live TV FirstPull` (client never pulled media). Dispatcharr `/proxy/ts/{id}` uses SharedHttpStream; PlaybackInfo clears unreachable origin Paths so clients must use `TranscodingUrl` / published LiveStreamFiles. See [`jellyfin_livetv_stream`](patches.md#jellyfin_livetv_streampatch) / [`jellyfin_livetv_published_url`](patches.md#jellyfin_livetv_published_urlpatch). |
| Live TV `NoCompatibleStream` (Wholphin) | Wholphin may send `MediaSourceId` = channel item Guid (placeholder) instead of the tuner source id. Without the workaround in [`jellyfin_livetv_published_url`](patches.md#jellyfin_livetv_published_urlpatch), PlaybackInfo returns empty sources / `NoCompatibleStream` in ~tens of ms with no live open. Server logs `Ignoring unmatched Live TV MediaSourceId` when falling back; AutoOpen then uses `MediaSources[0]` so a `LiveStreamId` is returned. Proper fix remains omitting `MediaSourceId` on first Live TV PlaybackInfo in the client. |
| Live TV `live.m3u8` null `OpenToken` | If PlaybackInfo skipped AutoOpen (or the client omitted `LiveStreamId`), `GetLiveHlsStream` used to build ffmpeg `-i` from the tuner origin before open, then `StreamState.Dispose` closed the stream (`ArgumentNullException` on null `OpenToken`). Mitigated by AutoOpen fallback ([`jellyfin_livetv_published_url`](patches.md#jellyfin_livetv_published_urlpatch)), open-before-CLI ([`jellyfin_livetv_stream`](patches.md#jellyfin_livetv_streampatch)), and `Request.LiveStreamId` sync ([`jellyfin_transcoding_pipeline`](patches.md#jellyfin_transcoding_pipelinepatch)). |
| Live TV open timeout | Shared HTTP (M3U) opens use `LiveStreamOpenTimeoutMs` (default 15000) so a stalled upstream fails that tune instead of waiting ~100s on `HttpClient.Timeout`. With [`jellyfin_livetv_stream`](patches.md#jellyfin_livetv_streampatch), that open no longer holds the global live-stream lock (same-channel opens are serialized by `OpenToken`); other channels/users are not frozen. Residual pause/zombie opens without session mappings are closed after a 2-minute grace by the inactive/idle sweeper. Adjust timeout under Dashboard → Playback → Transcoding (or UI Next admin → Playback → Transcoding). |
| UI Next live tuner cleanup | Stop reports carry `LiveStreamId` so the server can close the tuner. Failed or unavailable stop delivery uses one explicit close per acquired stream lease. Retained replacements share that lease, and failed or abandoned negotiations release resources they opened. Browser fixtures verify successful stop, failed-stop fallback, and abandoned tune cleanup. Consumer counts and account or route cleanup still need verification against a real tuner. Network loss can prevent both cleanup requests from arriving; the server's idle sweep remains the final cleanup path. |
| Live TV Multiview | UI Next does not include a Multiview player. The server still exposes `EnableLiveTvMultiview` for clients that implement it; each additional stream uses tuner and transcoding capacity. |
| Transcode codec parallel race | When [`EnableParallelCodecRace`](patches.md#jellyfin_z_transcode_codec_fallbackpatch) is on, HLS init may launch two full ffmpeg jobs (AV1 + H.264) briefly — expect doubled GPU/CPU load during startup until one wins. Cap is two concurrent races server-wide. HLS fmp4 init path only (not DASH/progressive in v1). |
| AV1 hardware encode | `AllowAv1Encoding` + NVENC still requires Ada-or-newer for reliable AV1 **encode**; pre-Ada GPUs may list `av1_nvenc` but fail at runtime. Fallback/race mitigates playback failures; software AV1 remains last in the sequential chain. See [`jellyfin_z_transcode_codec_fallback`](patches.md#jellyfin_z_transcode_codec_fallbackpatch). |
| SQLite migration | Stop Jellyfin first; target PG database should be empty; one-shot completion marker prevents re-runs ([README](../README.md#migrating-from-sqlite-to-postgresql)). |
| `Update_12_0-rc4` `PK_LinkedChildren` | rc4 changes `LinkedChildren` PK from `(ParentId, ChildId)` to `(ParentId, SortOrder)`. Production libraries often have many children with `SortOrder` NULL/0, so PostgreSQL error `23505` / `could not create unique index "PK_LinkedChildren"` aborts startup and the plugin restores the pre-migration dump. Images after this fix renumber sort order per parent before adding the PK (no children dropped). Re-pull the image and start once; the restore already left the DB on the previous schema. |
| `Update_12_0-rc5` dropped `IX_MediaSegments_ItemId` | rc5 sync compared the plugin snapshot (which had the QoS `ItemId` index) to the core model (which does not) and emitted a drop. `HasSegments` / `GetSegments` / extraction skip-checks then sequential-scan `MediaSegments` on every media-source build and congest the whole API. Fixed by `RestoreMediaSegmentsItemIdIndex` plus declaring the index in plugin `OnModelCreating` so later `Update_*` syncs keep it. Restart once after pulling an image that includes that migration. |
| `Update_12_0-rc4` dropped `IX_PlaybackActivity_SeriesId_DatePlayed` | Same class of sync drift: the plugin-only `(SeriesId, DatePlayed)` index is not in the core EF model, so rc4 emitted a drop. Taste episode rollup and series-scoped playback reads then scan `PlaybackActivity`. Fixed by `RestorePlaybackActivitySeriesIdDatePlayedIndex` plus declaring the index in plugin `OnModelCreating`. Restart once after pulling an image that includes that migration. |
| `AddUserTasteBecauseYouRecommendations` `42P07` already exists | A prior image or failed startup can leave `UserTasteBecauseYouRecommendations` in PostgreSQL without a matching `__EFMigrationsHistory` row; the next boot then fails `CREATE TABLE`, restores the pre-migration dump, and loops. The migration now uses `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`. Re-pull the image and restart once. |
| Active-standby HA | Off by default (`Pgsql_HA_ENABLED`). `/config` is still single-writer (share `JELLYFIN_SERVER_ID` if pods do not share `device.txt`). In-flight TCP, HLS, and Live TV sockets close on failover. UI Next retries `LiveStreamFenced` once; other clients may need a playback restart. Sidecar Redis on localhost cannot elect or overlay progress across pods. Extract Redis first. When enabling HA, switch k8s readiness from `/health` to `/health/ready`. |
| Playback error messaging (mobile) | Jellyfin Android, Swiftfin, and other clients do not yet consume `X-Playback-Error-Code` or the extended `PlaybackErrorCode` enum. They may show generic errors for mid-stream failures until updated. UI Next maps the server codes to its own recovery actions. |
| Movies Recommendations 524 under neural serving | Live `/Movies/Recommendations` used to run ML.NET over unbounded similar-item overlap (Cloudflare origin timeout ~100s). Because you watched/liked lists are now materialized by **Rebuild user taste recommendations** and served from `UserTasteBecauseYouRecommendations`. Titles watched after the last refresh still get a category via similarity + linear only until the next job. |
| Transcode codec fallback | With [`EnableTranscodeCodecFallback`](patches.md#jellyfin_z_transcode_codec_fallbackpatch), sequential fallback could dispose the live job's `CancellationTokenSource` while ffmpeg was still running. Playback then stopped while orphan transcodes accumulated, and `POST /Sessions/Playing/Stopped` threw `ObjectDisposedException`. The server patch now keeps the token source on success and stops failed attempts. |
| Redis query-cache health flapping | The original 100 ms synchronous operation deadline was too aggressive under short local Redis stalls, repeatedly marking a healthy connection unavailable and increasing PostgreSQL fallback load. The default is now 250 ms and configurable with `Pgsql_REDIS_OPERATION_TIMEOUT_MS` (50-5000 ms); genuine failures still fail open to memory until a background probe succeeds. |
| HLS missing-segment waits and remux timing | Previous HLS patch versions could wait forever for a missing segment inside the current generation and advertised equal-length segments for stream copy, although FFmpeg cuts at source keyframes. The consolidated [`jellyfin_zzzzzzz_hls_remux_segment_restart`](patches.md#jellyfin_zzzzzzz_hls_remux_segment_restartpatch) preserves keyframe-aware timing, regenerates missing past segments, bounds readiness waits to 30 seconds, and releases request counts on failure or disconnect. See [pantherale0#17](https://github.com/pantherale0/Jellyfin.Pgsql/issues/17). |
| HLS cleanup races and variable-length segment retention | Delayed cleanup could delete files produced by a replacement job under the same playlist name. A queued cleaner callback could also delete files after stop, and nominal-length index arithmetic could remove segments inside the retention window. [`jellyfin_zzzzzzz_hls_remux_segment_restart`](patches.md#jellyfin_zzzzzzz_hls_remux_segment_restartpatch) coordinates artifact ownership, ignores duplicate stops, stops queued deletions, and uses actual downloaded segment timestamps. Apply the full patch series when updating. |
| RO media mounts + subtitles | Automated “Download missing subtitles” / scan downloads are skipped when save-beside-media targets a read-only folder ([`jellyfin_subtitle_ro_skip`](patches.md#jellyfin_subtitle_ro_skippatch)). Manual downloads still attempt the media folder and will fail on RO mounts unless “Save subtitles into media folders” is unchecked. |
| Deep SortName `/Items` browse | Recursive Movie (and similar) library pages used to take ~10s+ on Count+`PresentationUniqueKey` GroupBy. Mitigated by [`jellyfin_z_items_browse_perf`](patches.md#jellyfin_z_items_browse_perfpatch) and optional browse ID-page cache (`Pgsql_CACHE_BROWSE_TTL`). Huge libraries may still need EXPLAIN verification. |
| Last administrator across HA nodes | [`jellyfin_zz_last_admin_invariant`](patches.md#jellyfin_zz_last_admin_invariantpatch) serializes deletes and demotions inside one server process. With several active HA instances, two nodes could still each remove a different last administrator at the same moment; perform user administration on one node. |
| UI Next music playback | Music uses HTML audio elements. Gapless playback is best-effort (the preloaded next track starts on `ended`, so a short gap is possible). iPhone and iPad Safari ignore page-set volume, so volume levelling, crossfade and the volume slider are unavailable there. The music queue is held in the page and is lost on reload; background playback depends on the browser or wrapper keeping the page alive. See [UI Next README: Compatibility](../ui-next/README.md#compatibility-and-current-gaps). |
| UI Next translations and RTL | UI Next uses local English and locale catalogs. New messages remain in English until translated. The TV on-screen search keyboard is Latin-only. Right-to-left layout was checked by screenshot in Arabic only. See [UI Next README: Translations](../ui-next/README.md#translations). |
| UI Next admin telemetry/API coverage | Admin pages use existing Jellyfin and Pgsql endpoints. PostgreSQL connection, size, and query internals, per-mount managed paths, tuner active-stream pressure, Multiview permission usage, Seerr queue depth, and last SSO sync are not exposed by current APIs; these pages omit unavailable measurements. Pgsql environment-variable overrides are read-only. Jellyfin has no global DVR retention setting, so the DVR settings page does not offer one. Per-device playback overrides are available under System → Devices. |
| Alphabet browse-cache collision (older plugin versions) | Cache keys omitted `NameStartsWith`, `NameStartsWithOrGreater`, and `NameLessThan`, letting different letters reuse another boundary's IDs and total count. Fixed in `Query/QueryCacheKeyBuilder.cs`; the changed canonical key also separates new entries from old ones. Deploy the updated plugin/image for existing web clients. UI Next uses absolute-index probes instead of boundary-count requests and works around older servers. |
| UI Next list metadata latency | Requesting `People` for an entire 80-title page can exceed the client's 20s deadline on large libraries. List pages now load without `People`; director names are requested separately for mounted rows near the viewport, cancelled on unmount, and remain “Director unknown” if enrichment fails. |
| UI Next first alphabet jump | An uncached letter requires logarithmic, sequential single-item probes followed by a page fetch. Cold filtered queries can make this noticeably slower than ordinary paging; repeat jumps reuse the offset until the library/query/view changes. The bubble updates immediately during dragging, and superseded work is cancelled. |
